# V3 — 화자 귀속 보정(턴 시작 교대 결정) (2026-10-21)

사용자: "화자 귀속 문제를 완화해서 VibeVoice 에 비해 TAXI 에서 우위를 점하고 싶은데, 최근 연구들을 조사하고 문제를 완화할 수 있는 방안은 모색해. 그래서 이를 적용한 모델이나 기법을 V3 로 명명해서 적용해줘." 이어서 "기존의 방식에서의 문제점 등도 함께 검토하고 발전시킬 수 있는 점이 있으면 개선하고".

진행 방식(ultracode 워크플로):
1. 조사 워크플로(8 에이전트): 문헌 다섯 갈래, 기존 방식 검토 둘, TAXI 오류 해부 하나
2. 설계 패널(16 에이전트): 설계 넷, 인용 검증 여덟, 심사 셋, 종합 하나
3. 구현 워크플로(4 에이전트, worktree 분리)

TAXI 는 평가 전용이다. 어떤 값·체크포인트·변형도 TAXI 로 고르지 않는다. TAXI 전사·가설은 mxc 에만 두고 여기에는 집계만 적는다.

## 1. TAXI 차이는 전부 화자 귀속이다

같은 정규화(두 언어 공통 — 소문자·문장부호 제거)로 cp 와 화자 무시 agn 을 함께 쟀다. `cst_stage4_taxi.py score` 의 `split` 이 같은 값을 낸다.

| | cp | agn | 귀속 몫 |
|---|---:|---:|---:|
| VibeVoice-ASR-Streaming-7B | 20.5 | 20.1 | 0.4 |
| VibeVoice-ASR 오프라인 | 16.8 | 16.5 | 0.3 |
| V1 = st4-m2a ck2000, 세션 통째, δ10 | 26.4 | **18.4** | 8.0 |
| V2 = v2-p1 ck2000, 세션 통째, δ10 | 30.6 | 20.3 | 10.2 |

받아쓰기는 이미 VibeVoice 스트리밍보다 낫다. 귀속 몫을 줄이면 앞선다.

## 2. 오류 해부 (V1, δ10, `scratchpad/v3diag` 의 정렬 분석 — 집계만)
- TAXI: 86 세션, 턴 640, 교대 540, 겹침 0, 턴 사이 간격 0–1 s(중앙 0.22 s). 독일어 배차원이 85/86 세션을 연다. 화자 레벨 차 중앙 6.35 dB(q90 14 dB), 양쪽 8 kHz 전화.
- 틀린 단어의 94 % 가 턴 전체가 틀린 턴, 98 % 가 교대 턴에 있다. **89 % 가 턴 시작에서 태그를 내지 않은 뒤에 온다**(놓친 교대).
- 모델은 교대를 덜 낸다. 가설 교대 496 대 참조 540(VibeVoice 548). toggle recall 87.4 %(VibeVoice 98.1 %). 턴 안 오교대는 단어 쌍의 0.3 % 뿐이다.
- 첫 턴은 86/86 이 맞다(첫 화자가 슬롯 B 인 44 세션 포함). 슬롯 초기화·flip 은 상관없다(7.9 % 대 7.8 %).
- 전형 오류는 한 턴을 삼키는 것이다(A, B, A 가 모두 A 슬롯). 72 % 는 다음 교대도 놓쳐 다시 맞춰진다. 역전 연쇄는 6–10 %.
- 영어 손님 턴이 독일어 배차원 슬롯에 삼켜지는 비율이 반대보다 2.7 배다(9.3 % 대 3.5 %). 3 단어 이하 턴은 14.9 % 대 7.9 %.
- 삼킨 턴 단어의 절반은 제 언어로 맞게 받아썼고, 절반은 틀린 슬롯의 언어로 번역·의역됐다(선언 언어가 강제 사전확률이 된다).
- 오라클로 단어를 맞는 슬롯에 옮기면 cp 26.5 → 18.3(= agn). 번역 누출까지 없애면 약 16 이다(VibeVoice 오프라인 16.8 보다 낮다).
- V2 도 같은 유형이고 놓침만 많다(toggle recall 79.6 %, 탭을 끄면 75.2 %). δ4·δ10, 40 s 창은 귀속이 같다.

## 3. <EOT> 진단 (`taxi_v3_probe.py`·`taxi_v3_probe.sh`, V1 st4-m2a ck2000, 세션 통째, δ10)

| 슬롯 태그 bias(진단 전용) | <EOT> 방출 | cp | agn | 귀속 몫 |
|---|---:|---:|---:|---:|
| 0 | **0** | 26.4 | 18.4 | 8.0 |
| 1.5 | 7 | 36.3 | 27.7 | 8.7 |
| 3 | 204 | 640.3 | 637.5 | 2.8 (붕괴 — 태그 토큰 92,331 개) |

- bias 0 에서 태그 토큰은 5,280 개(세션당 약 61)다. 번역 모드는 번역 구간이 끝날 때마다 같은 슬롯 태그를 다시 연다.

- **V1 은 교차 언어 TAXI 에서 <EOT> 를 하나도 내지 않는다.** 교차 언어 학습 창은 합성뿐이고, 합성 <EOT> 는 라벨이 −100(meta.mask_eot)이라 내는 법을 배운 적이 없다.
- 그런데 학습 시퀀스에서는 그 <EOT> 가 teacher forcing 문맥에 남아 있고, 번역 모드의 교대는 모두 <EOT> 뒤에 온다(설계 패널 점검 1598/1598).
- 그래서 모델은 '자기 <EOT> 뒤에 교대'를 배웠는데, 추론에서는 그 <EOT> 가 오지 않는다. 학습·추론 불일치가 놓친 교대를 설명한다.
- 두 태그에 같은 bias 를 더하면 받아쓰기까지 크게 나빠진다(agn 27.7). 균일 bias 는 답이 아니다. 이 값은 진단으로만 읽는다.

## 4. 문헌 (검증한 인용만)
- 교대 토큰 방식의 약점은 놓친 교대다. 교대 재현율을 겨눈 손실이 효과가 있었다: Zhao et al., ICASSP 2023, arXiv:2211.06482 — FA/FR 가중 손실로 recall 55.8 → 65.2(precision 78.1 → 77.6).
- 추론 때 교대 토큰 사후확률을 키우면 F1 이 오른다: USM-SCD, arXiv:2309.08023 — λ=5 로 F1 64.6 → 75.3(96 개 언어, 설정이 우리와 다르다).
- 단어 수준 화자 결정과 짧은 지연: Kanda et al., Interspeech 2022, arXiv:2203.16685 — t-vector 결정 지연 0/1/2/4/8 단어에서 LibriCSS cpWER 13.1/12.7/12.4/14.3/19.7.
- 화자 증거를 디코더에 넣을 때는 화자 목적함수가 있어야 한다: Sortformer(ICML 2025, arXiv:2409.06656) 커널 주입 AMI cpWER 32.94 → 28.17, JEDIS-LLM(arXiv:2511.16046) 학습 전용 단어 수준 화자 디코더로 AMI WDER 10.87 → 6.97. 목적함수 없는 raw 탭(우리 V2-a)은 귀속을 바꾸지 못했다.
- 턴마다 화자 결정을 다시 선언하는 형식: Zheng et al., Interspeech 2026, arXiv:2606.13095(virtual <SC>). 저자 목적은 정밀도·견고성이라 recall 근거로는 약하다.
- 비교 기준: VibeVoice-ASR-Streaming 기술 보고서(arXiv:2609.02812) — 청크 2.0/2.9 s, lookahead 약 0.5 s, 알고리즘적 화자 지연 1.53–2.00 s, 7B, 스트리밍 사전학습 약 420k h.
- 인용 검증에서 두 주장은 반박됐다(구글 두 논문을 섞은 인용, Streaming Sortformer AOSC 수치). 위 목록은 고친 인용이다.

## 5. 기존 방식의 문제(검토 결과)
- 태그는 교대 때만 낸다. 그래서 교대를 놓쳐도 그 자리에서는 손해가 없다.
- mono Stage 3/4 의 슬롯 태그 가중이 1 이다(`modeling_vapasr.py` 의 tag_weight 는 Phase 2 lanes 에만).
- 합성 <EOT> 는 감독하지 않으면서 문맥에는 남긴다(3 절의 불일치).
- 교차 언어 합성 쌍은 100 % 서로 다른 코퍼스다(영어 쪽 8 kHz Switchboard·낭독 대 독일어 광대역 대화). 교대가 곧 채널·코퍼스 교대라 지름길이 있다.
- 전화 대역 증강은 창 단위라 두 화자에게 같다. 화자 레벨 차는 ±3 dB 까지다. TAXI 는 서로 다른 두 전화 회선, 레벨 차 중앙 6.35 dB 다.
- 합성 턴 타이밍은 같은 화자 지속 30 %, 겹침 23 %, 맞장구가 있다. TAXI 는 엄격 교대(같은 화자 지속 2.5 %), 겹침·맞장구 없음이다.
- 화자 활동 헤드는 지금 청크를 라벨로 쓴다(δ 정렬이 아니다). 디코드에서는 하드 삽입으로만 쓰였고 손해였다(+4 pt).
- 정체 회복 학습은 같은 언어 2 슬롯 받아쓰기 창에만 걸리고, 번역 모드·교차 언어 창에는 닿지 않는다.
- 평가: 턴 결정 지표(toggle recall 등)가 없었고, TAXI 없이 튜닝할 전화 dev 가 없었다.

## 6. V3-p1 설계 (설계 패널 종합 `v3-design-spec.txt` 요약 — 조사 요약 `v3-research-digest.txt`, 근거 묶음 `v3-evidence.md`, 오류 해부 스크립트 `diag/`)
모든 구성 요소는 기본값이 꺼짐이고, 끄면 기존과 시퀀스·난수·출력이 같다. 바탕 레시피는 V1 = st4-m2a(2 슬롯, 20–40 s 창, split v2, 전화 대역 0.3, 2,500 step, init p11 ck3000)다. 기존 st4-m2a ck1500·ck2000·final 이 대조군이다.
- **C5 교차 언어 합성 창의 <EOT> 문맥 제거**(3 절 E− 분기): 감독하지 않는 합성 <EOT> 를 문맥에서 뺀다. 그 자리 <NEXT_AUDIO> 라벨은 −100 으로 둔다('여기는 EOT 아님'을 가르치지 않게). V3-p1 값은 교차 언어 셋 p = 1.0 이다(추론에서 교차 언어 <EOT> 는 나오지 않으므로).
- **C1 교대·머무름 결정 가중**: 교대 태그(다음 토큰이 단어 첫 토큰인 경우만)에 pos_weight 3, <EOT> 뒤 같은 화자 머무름 결정에 1.5. 모델 손실 식은 그대로이고 결정 통계만 로그에 남긴다.
- **C2 2 회선 전화 교차 언어 합성 `sim_en-de-tel`**: 화자별 독립 전화 대역, 레벨 ±8 dB, 엄격 교대(같은 화자 지속 0.05, 간격 0.05–0.8 s, 턴 안 쉼 < 0.25 s, 맞장구 없음), 10 % 는 두 화자 같은 채널. 가중 1.0, 기존 sim_en-de 는 0.5.
- **C3 상태 인지 교대 bias(디코드 전용)**: 교차 언어 prefix 에서만, 현재가 아닌 슬롯 태그에만, 결정 지점(<EOT> 뒤·<TRANS> 뒤 재개·전사 단어 시작)별로 준다. 값은 C4 dev 의 tune 반쪽에서 고르고 check 반쪽에서 확인한다.
- **C4 비-TAXI 전화 dev(`sim-dialogue-xl-tel-eval-v1` → TAXI 형식)와 턴 결정 지표(`cst_attr_turns.py`)**: toggle recall, 교대 수 비, 턴 통째 오류, 턴 안 오교대, 방향별 놓침, 번역 누출, 세션 짝 bootstrap.
- **S0 진단**: 놓친 onset 의 토큰 문맥 분류(OK·RESUME·REASSERT·SILENT·ABSORBED), --asr-only 디코드, teacher-forced 교대 정확도의 <EOT> 의존도(dTF).
- 학습: R1 `v3-p1` = C1 + C2 + C5, R2 `v3-p1-nodata` = C1 + C5(tel 셋 없이) — 같은 step·seed. R1 − R2 = C2 효과, R2 − V1 = C1 + C5 효과.
- 목표(TAXI, 보고 전용): 귀속 몫 ≤ 3(확장 ≤ 1.5), cp < 20.5(VibeVoice 스트리밍, 확장 < 16.8), agn ≤ 18.4. toggle recall ≥ 95 %.
- 가드(V1 ck2000 대비): agn +0.3 이내, 같은 언어 귀속 몫 악화 ≤ 0.2, EOT P/R −0.01 이내, 단일 화자 +0.2–0.3 이내, 번역 BLEU −0.5 이내, 합성 영어 반복.
- 미룬 것(p2/p3): 턴 헤더 형식, <SRC> 재개 토큰, Switchboard 같은 통화 실제 2 회선, tel 셋 교대 <EOT> 감독, 교차 언어 놓침 회복·on-policy 교정, 교차 언어 lookahead, 단어 정렬 슬롯 헤드(라벨 지연 사용자 결정), 같은 언어 화자 표현 분기.
