어느 클래스가 우세하냐에 따라 맞는 해법이 다르다.
- RESUME: <TRANS> 뒤 같은 슬롯 재개. 결정 bias (ii), C5, 형식 C 가 후보다.
- REASSERT: <EOT> 뒤 같은 슬롯을 명시적으로 잘못 고름. 데이터·지각 쪽 문제다.
- SILENT: 전사 kind 무태그 계속. 헤더 형식이 후보다.
- ABSORBED: 번역 kind 로 흡수(언어 강제). lookahead 와 회복 학습이 후보다.

### C1 교대·머무름 결정 가중: 교대 태그 pos_weight 3, <EOT> 뒤 머무름 1.5, 결정 통계 로깅 [p1=True]
RATIONALE: mono Stage 3/4 는 슬롯 태그 가중이 1 이다. modeling_vapasr.py:148 의 tag_ids/tag_weight 가 lanes>0 일 때만 켜지기 때문이다.

교대는 드물고(턴당 약 1 토큰) 번역 모드에서는 같은 슬롯 재개와 경쟁한다(dry-xl: 번역 모드 창당 태그 34.7 대 받아쓰기 8.3, 합성 점검 재개 3656 대 교대 1598). 모델은 교대를 덜 낸다(496 대 540). 턴 안 오교대는 0.3% 라 recall 을 올릴 여유가 크다.

모델 변경이 필요 없다. p2_losses.soft_ce 의 pos_override 가 가중 우선순위 최상위이고, pos_weight 는 이미 packing ROW_KEY 다.

머무름 가중 1.5 는 judge 가 지적한 같은 언어 정밀도 위험(실제 대화 episode p_hold 0.58)을 막는다. <EOT> 뒤 결정의 두 결과를 모두 감독하되 recall 쪽에 더 무게를 둔다(3 대 1.5).

문헌: Zhao et al. ICASSP 2023 의 FA/FR 가중 손실은 precision 78.1→77.6 에서 recall 을 55.8→65.2 로 올렸다. G-STAR 의 2x speaker-token CE 는 주로 DER 을 개선했으므로 가중만으로 큰 cp 이득을 기대하지는 않는다.
IMPL: vapasr/data/cst_dialogue.py

새 순수 함수 decision_positions(ids, is_input, labels, labels_alt, src_at, spk_ids, trans_id, eot_id, word_start) → (switch: List[int], hold: List[int]).
- 문맥 슬롯 cur 을 시퀀스를 따라 추적한다. 입력·출력·마스크 여부와 상관없이 모든 슬롯 태그가 cur 을 갱신한다. <TRANS> 는 kind 만 바꾼다.
- switch 위치 p 의 조건(모두 만족):
  - labels[p]==ids[p] 이고 ids[p] ∈ spk_ids
  - cur 이 있고 slot(ids[p]) 과 다름
  - labels_alt[p]==-100
  - ids[p+1] 이 출력 텍스트이고 word_start 가 True
  이 조건으로 <EOT> 를 위해 연 태그, <SPK><TRANS>, 첫 태그, 단어 중간 overlap churn 이 빠진다.
- hold 위치 p: 출력 <EOT>(슬롯 s) 뒤 첫 출력 결정 토큰이다. <NEXT_AUDIO> 와 오디오 입력은 건너뛴다. 조건은 다음 둘 중 하나이고, labels[p]!=-100 이며 labels_alt[p]==-100 이어야 한다.
  - 같은 슬롯 <SPK_s>(번역 모드 재개)
  - 슬롯 s 문맥의 word-initial 텍스트(받아쓰기 모드에서 태그 없이 계속)

build_cst_sequence 와 build_cst4_sequence 에 change_weight=0.0, hold_weight=0.0, word_start=None 을 추가한다(word_start 는 cst4 에 새로 넣는다).
- 값이 >0 이면 해당 위치에 pos_weight[p] = max(pos_weight[p], w) 를 적용한다. 그래서 기존 <EOT> decision_weight 2.0 위치는 그대로다.
- 둘 중 하나라도 >0 일 때만 dec_kind (L,) int8 {0, 1=switch, 2=hold}, n_switch, n_hold 를 반환한다.

CstDialogueDataset(change_weight=0.0, hold_weight=0.0, weight_sets=None).
- cst_sequence 와 cst4_sequence 로 값을 넘긴다. cst4 에는 word_start=self.word_start 도 넘긴다.
- collate_cst 가 dec_kind 를 (B, L) 로 패딩한다(키가 없으면 만들지 않는다).
- packing.ROW_KEYS 에 'dec_kind' 를 추가한다. 없는 키는 기존 규약대로 건너뛴다. stage3_train IN_KEYS 에도 추가한다.

- 주어지면 통계만 계산한다: top1_switch, loss_switch, top1_hold, switch_miss(argmax 가 텍스트), switch_wrong_slot(argmax 가 현재 슬롯 태그).

problems_of / problems_of4: 가중을 켰을 때 'switch_w' 를 검사한다. 가중 위치 집합이 decision_positions 와 같아야 하고, 각 교대 태그는 직전 문맥 슬롯과 달라야 한다. 'hold_w' 도 같은 방식으로 검사한다.

### C2 sim_en-de-tel: 2회선 전화 조건의 교차 언어 합성 셋. 화자별 독립 전화 대역, ±8 dB 레벨 차, 엄격 교대, 턴 안 쉼 <0.25 s, 10% 동일 채널 [p1=True]
RATIONALE: xl 합성에는 교대 지름길이 있다.
- 모든 쌍이 서로 다른 코퍼스다(EN 풀에 8 kHz Switchboard·낭독, DE 는 광대역 KEC/ZTC/NSC).
- phone aug 는 창 단위라 두 화자에게 똑같이 걸린다(cst_dialogue.py:713).
- 레벨 jitter 는 ±3 dB 다(sim_build_dialogues.py:114).
그래서 모델은 '채널이 바뀌면 교대'를 배울 수 있었는데, TAXI 에는 그 단서가 없다(양쪽 8 kHz, 스펙트럼 중심 632 대 654 Hz).

합성 타이밍도 TAXI 와 다르다(SimConfig, sim_dialogue.py:248-257).
- p_hold 0.3, FTO overlap 23%, 맞장구가 있다.
- intra_pause 0.1-0.5 s 가 0.25 s episode 경계를 넘어서, 턴 안에 같은 화자 <EOT> 가 생긴다.
- TAXI 는 교대 97.5%, 간격 0.05-0.54 s, overlap 0, 레벨 차 중앙 6.35 dB 다.

데이터는 이 지표를 실제로 움직였다. phone aug 0.3 하나로 TAXI cp 가 40.9→28.1 이 됐고, V2 의 데이터 이동은 toggle recall 을 87.4→79.6 으로 떨어뜨렸다.

TAXI 를 보지 않고 일반적인 전화 조건 범위로 만든다. 10% 는 두 화자가 같은 채널이라 '선이 다르면 화자가 다르다'는 새 지름길을 막는다.

### C3 상태 인지 교대 bias (디코드 전용, 교차 언어 prefix 만, 결정 지점별 β, dev 에서만 튜닝) [p1=True]
RATIONALE: TAXI 번역 모드 디코드에서는 onset 의 상당수가 이미 명시적 태그 선택이다(<TRANS> 뒤나 <EOT> 뒤). 진행 중인 균일 tag-bias 프로브는 두 태그에 같은 +b 를 더하므로 이 A/B 선택을 바꾸지 못한다.

현재 슬롯 기준으로 '다른 슬롯'에만 bias 를 주고 결정 지점을 나누면, 태그 누락(SILENT)과 같은 슬롯 재개(RESUME/REASSERT)를 둘 다 뒤집을 수 있다.

정밀도 여유가 크다(턴 안 오교대 0.3%). 예전 하드 삽입(+4.06 cp)은 흔들리는 청크 단위 헤드로 태그를 넣었다. 이 방식은 모델 자신의 태그 logit 만 옮긴다.

번역 kind 안의 word-start 와 단어 중간에는 걸지 않는다. 턴 안 재개가 교대보다 약 2.3 배 많아서 거기에 걸면 오교대와 번역 churn 이 생긴다.

문헌: USM-SCD(arXiv:2309.08023)는 추론 때 <st> 사후확률에 λ=5 를 곱해 F1 64.6→75.3 을 얻었다. 다만 YT-96 다국어, greedy 설정이다.
IMPL: vapasr/hf/batch_decode.py 에 dataclass SwitchBias(b_eot=0.0, b_res=0.0, b_wi=0.0, modes=('xl',)) 를 추가하고 decode_batch(..., switch_bias=None) 로 받는다.

행별 상태는 emitted 토큰으로 갱신하며 parse_emitted4 와 같은 규칙을 쓴다.
- cur: 마지막 슬롯 태그, 없으면 None
- kind: 0 또는 1
- eot_open: 이 행이 <EOT> 를 낸 뒤 아직 슬롯 태그가 없음

mode 는 행마다 한 번, prefix 에서 슬롯 태그 뒤 언어 이름이 서로 다르면 'xl' 이다.

argmax tid 에 대해, cur 이 있고 mode ∈ modes 이고 advance 가 아닐 때:
- (i) eot_open 이고 tid 가 <SPK_cur> 또는 word-initial 텍스트 → b_eot
- (ii) eot_open 이 아니고 kind==1 이며 tid==<SPK_cur>(번역 뒤 재개) → b_res
- (iii) eot_open 이 아니고 kind==0 이며 tid 가 word-initial 텍스트 → b_wi
해당하면 그 행 logits 를 복제해 <SPK_other> 에 b 를 더하고, 다시 argmax 해 <SPK_other> 가 이기면 교체한다.

그 밖의 위치는 건드리지 않는다: 번역 kind word-start, 단어 중간, 첫 태그, <NEXT_AUDIO>, <EMPTY_AUDIO>, <TRANS>, <EOT>.

word_init (V,) bool 은 tok.decode([t]).startswith(' ') 로 한 번 캐시한다(spk_guide 의 word_start 재사용). 카운터 s.sb_flips = {eot, res, wi}.

switch_bias=None 이면 블록을 통째로 건너뛰어 토큰이 같다. 직렬 stream_decode(--verify)는 bias 를 지원하지 않으므로 bias≠0 이면 verify 를 assert 로 거부한다.

배선: cst_stage4_taxi.py run, cst_stage4_eval.py run, cst_stage3_eval.py run 에 --switch-bias 'eot=..,res=..,wi=..[;…]' 를 추가한다. --deltas 처럼 같은 인코더 특징을 재사용하고, 출력은 <out>/sb-<tag>/ 와 config.json 이다. 동결한 값은 결과 디렉터리의 decode_policy.json 에 남긴다.

튜닝은 dev 에서만 하고 설정을 동결한 뒤 TAXI 를 한 번 돌린다.
- xl-tel-dev 160 세션을 tune 80 / check 80 으로 나눈다.
- 단계 격자: b_eot ∈ {0,1,2,3} → 그 최적에서 b_res ∈ {0,0.5,1,2} → b_wi ∈ {0,0.5,1}.
- 사전 등록 규칙: tune 반쪽의 attribution share 최소. 단 다음 조건을 지킨다.
  - 턴 안 오교대 ≤0.6%
  - hyp/ref change ratio ≤1.05
  - early-switch partial words ≤ 같은 체크포인트 b=0 의 2 배
  - xl-eval-v1 번역 BLEU −0.5 이내
- check 반쪽에서 b=0 대비 paired session bootstrap 95% CI 가 0 을 넘을 때만 채택하고, 아니면 해당 β 를 0 으로 둔다.
- 같은 언어 prefix 는 0 으로 고정한다(modes=('xl',)).
- δ10 에서만 튜닝하고 δ4 는 같은 값으로 보고한다.
FLAG: decode_batch(switch_bias=None), eval/TAXI 스크립트에서 --switch-bias 미지정 → 기존 토큰열 그대로. live App(MLX) 디코더는 바꾸지 않는다.

### C5 합성 창 EOT-문맥 dropout (p=0.5, Step 0 규칙에 따라 켜고 끔) [p1=True]
RATIONALE: 합성·xl 창은 meta.mask_eot 로 <EOT> 결정 라벨이 −100 이다. 그런데 <EOT> 자체는 문맥에 남는다(cst_dialogue.py:85-87).

합성 점검을 보면 번역 모드 교대는 TAXI형 간격에서 100% <EOT> 뒤에 오고, 학습형 FTO 에서도 <EOT> 없는 교대가 57 대 같은 슬롯 재개 3020 으로 드물다. 모델은 '자기가 <EOT> 를 냈을 때만 교대'를 배웠을 수 있다. 그런데 교차 언어 전화 오디오에서 <EOT> 를 내는 법은 감독받은 적이 없다. 이 조합이면 통째로 삼킨 턴이 그대로 설명된다.

dropout 은 감독을 잃지 않는다. 합성 <EOT> 는 원래 −100 이고, 실제 대화는 건드리지 않는다. 남는 위험은 유효한 단서가 약해지는 것이다. 그래서 합성 창의 절반에만 적용하고, dev 의 EOT 지표로 지킨다.
IMPL: cst_dialogue.window_streams / window_streams4(..., drop_eot=False):
- True 면 p_end 가 None 인(합성) episode 의 <EOT> 원소, eot_p, eot_tail 을 넣지 않는다.
- 대신 ghost(슬롯, k_min, tails) 를 반환하고 st['eot_dropped'] 를 센다.

build_cst_sequence / build_cst4_sequence(..., eot_ghost=()):
- flatten_cst 뒤 각 ghost 의 청크 c = max(k_min, tails 방출 청크) 를 구한다.
- c<K 이면 그 라운드를 닫는 <NEXT_AUDIO> 라벨을 −100 으로 둔다('여기서는 EOT 가 아니다'라는 신호를 지운다).
- flush 라운드는 그대로 둔다.

CstDialogueDataset(eot_drop_synth=0.0): d.meta.mask_eot 인 창에서만, 그리고 p>0 일 때만 rng.random() 을 뽑는다.

problems_of / problems_of4: n_eot + eot_dropped = 창의 EOT 수인지, ghost 위치가 맞는지 검사한다.

stage3_train.py --eot-drop-synth: 지문 키는 >0 일 때만 쓴다.

p1 값은 0.5 다. R1 제출 전에 eot_contingency 규칙으로 켤지 끌지 정한다.
FLAG: --eot-drop-synth 0 (기본). 난수 소비, 시퀀스, 라벨, 지문이 같다.

- teacher-forced 교대 top-1 이 이미 ~100% 면 이 레버는 거의 효과가 없다. S0 dTF 와 학습 로그로 미리 보인다.

C2 tel 셋 위험과 대응:
- '선이 다르면 화자가 다르다'는 새 지름길 → 10% 동일 채널 세션을 넣는다.
- 클립된 FTO 경계(0.05, 0.8)에 값이 몰린다 → 수용하되 dev 로 확인한다.
- 이중 전화 처리 → --set-phone sim_en-de-tel:0.
- 다른 셋이 약 4% 희석되고 replay 비중이 32.4→31.0% 로 준다 → 단일 화자·FLEURS 가드.
- 여전히 영어 풀 대 독일어 풀이라 교차 코퍼스다 → 잔여 confound 는 P2-C/P2-F 에서 다룬다.
- 엄격 교대 사전확률이 같은 언어로 샐 수 있다 → 교차 언어 tel 셋에만 적용하고 같은 언어 sim 은 그대로 둔다.

C5 EOT-문맥 dropout:
- 유효한 '<EOT> 뒤 교대' 단서가 약해지고 실제 대화의 EOT 방출이 줄 수 있다.
- 대응: 합성 창의 50% 에만 건다. ghost 라운드의 <NEXT_AUDIO> 는 마스크한다. 실제 대화는 건드리지 않는다. EOT P/R 가드를 둔다. E+ 가 확실하면 끈다(dTF 와 D1 이 둘 다 E+ 일 때).

C3 디코드 bias:
- 오교대와 번역 churn 이 생길 수 있다.
- 대응:
  - 결정 지점 셋에만 걸고, 번역 kind 안과 단어 중간은 제외한다.
  - xl prefix 에만 걸고, 같은 언어는 0 으로 둔다.
  - tune/check 를 나눠 β 가 dev 에 과적합하지 않게 하고, check 반쪽에서 CI 가 0 을 넘을 때만 채택한다.
  - 슬롯 인덱스(B)가 아니라 '현재가 아닌 슬롯'에만 bias 를 준다(V2 의 슬롯 B 편향 선례).
- dev 최적 β 가 실제 통화로 잘 옮겨가지 않을 수 있다. 그래서 TAXI 는 b=0 과 b* 를 둘 다 보고한다.

dev 타당성:
- 합성 dev 는 순위 신호이지 수준 추정이 아니다.
- 경도 게이트를 둔다: V1 이 xl-tel-dev 에서 실제로 덜 맞혀야 한다.
- 여전히 순위가 TAXI 와 어긋날 수 있다. p2 에서 swbd-call-dev(실제 2회선)를 더해 보완한다.

TAXI 누출 금지:
- 값, 체크포인트, 플래그, 변형은 TAXI 로 고르지 않는다.
- D1 은 컴포넌트를 켜고 끄는 데에만 쓰고, 비-TAXI dTF 로 교차 확인한다.
- TAXI 는 체크포인트당 b=0 과 b* 로 정확히 두 번만 디코드한다.

통계: toggle recall SE ≈1.4 pt 이고 최악 10 세션이 75% 다. 세션 paired bootstrap, change ratio, 오교대 가드를 함께 보고하고, noise floor 미만의 이득은 주장하지 않는다.

EOT CONTINGENCY:
 측정 (설정이나 값을 정하기 전에 한다)
- f_miss: V1 d10 의 놓친 교대(직전 턴은 맞음, 새 턴은 틀림) 중에서, 직전 턴 마지막 가설 단어와 새 턴 첫 가설 단어 사이에 이전 슬롯의 <EOT> 가 방출된 비율. 출처는 eot_study 와 D1.
- f_hit: 잡은 교대에서 같은 비율.
- D1 클래스 분포: OK, RESUME, REASSERT, SILENT, ABSORBED.
- 비-TAXI 교차 확인: xl-tel-dev 에서 V1 의 dTF.
- 새 화자의 첫 단어보다 늦게 방출된 <EOT> 는 '없음'으로 센다.
- 이 측정은 컴포넌트를 켜고 끄는 데만 쓰고, 어떤 값도 고르지 않는다.

E+ : 경계는 들었는데 결정을 놓친 경우
조건: f_miss ≥0.7 이고 dTF <5 pt. 둘 다 만족해야 한다.
- p1 조정:
  - C5 를 끈다. 유효한 '<EOT> 뒤 교대' 단서를 지킨다.
  - C1 은 그대로 둔다(교대 3, 머무름 1.5).
  - C3 는 결정 지점 (i) b_eot 를 중심으로 튜닝한다. tel 조건에서 <EOT> 뒤 hold 는 드물어서(합성 0.05) 오교대 위험이 낮다. b_res 와 b_wi 는 격자에 남겨 dev 가 정하게 한다.
- p2 우선순위(D1 클래스로 정한다):
  - REASSERT, 즉 <EOT> 뒤 같은 슬롯을 명시적으로 잘못 고름이 우세: 결정의 형식이 아니라 증거와 슬롯의 결합 문제다. P2-C(Switchboard same-call 실제 2회선, EOT 감독), P2-F(확장 전화 체인, 레벨 ≥12 dB, F0·계열 짝), P2-G(lookahead, 디코드만)를 쓴다.
  - SILENT 가 받아쓰기 경로에서 크다: P2-A(헤더와 문법).
  - RESUME 이 우세하고 D2 asr-only 가 ≥2 pt 나으며 C3(ii) 가 dev 에서 실패한다: P2-B(<SRC>) 와 P2-A.

E- : 경계 자체를 놓친 경우
조건: 놓친 교대의 ≥30% 에 이전 슬롯 <EOT> 가 없거나, dTF ≥5 pt.
- p1 조정:
  - C5 를 켠다(--eot-drop-synth 0.5). R2 에도 똑같이 켜서 R1−R2 가 C2 효과만 남게 한다.
  - C3 는 (ii) <TRANS> 뒤 재개와 (iii) 전사 word-start 를 함께 튜닝한다. <EOT> 게이트 지점은 거의 발동하지 않는다.
  - 1 차 진단 지표는 TAXI 와 dev 의 교대 앞 <EOT> 비율, Stage 3 EOT F1 이다.
- p2 우선순위:
  - P2-D: tel 셋 교대 EOT 감독(mask_eot='change_only'). 실제 대화의 EOT 정밀도·지연 가드를 통과할 때만 유지한다.
  - P2-E: 번역 모드 XlMiss, 이어서 on-policy 교정. <EOT> 없이 1-3 단어 안에 교정하도록 가르친다.
  - P2-C: dlg_swbd. 실제 전화 타이밍에서 EOT 가 감독된다.
  - recall 이 여전히 95% 미만이면 V31-H(word-aligned slot head + 히스테리시스). 사용자가 라벨 지연을 결정해야 한다.
  - P2-A(헤더와 문법)는 순위를 낮춘다. <EOT> 가 없으면 헤더 문법이 발동하지 않는다.

혼합이거나 판단이 엇갈리는 경우
조건: 0.3 < (EOT 없는 비율) < 0.7 이면서 dTF 와 D1 이 엇갈림.
- C5 를 켠다. 감독을 잃지 않기 때문이다.
- 슬롯 여유가 있으면 R1 에서 C5 를 뺀 run 을 함께 돌린다.
- C3 세 지점을 모두 튜닝한다.
- p2 는 우세 클래스를 따른다.

공통
- C1, C2, C3 는 두 분기 모두에서 그대로 둔다.
  - 번역 모드에서 교대는 <EOT> 유무와 상관없이 명시적 태그 결정이다.
  - C2 는 채널 지름길을 없앤다.
- ABSORBED(번역 kind 로 흡수, 언어 강제)가 크면 분기와 상관없이 P2-G lookahead 와 P2-E 의 번역 변형을 앞으로 당긴다.
- D2(asr-only)가 번역 모드보다 크게 나으면 번역 형식이 원인으로 지목된 것이다. 이때 P2-B 의 우선순위를 올린다. 다만 TAXI 디코드 방식(번역 prefix)은 바꾸지 않는다.
