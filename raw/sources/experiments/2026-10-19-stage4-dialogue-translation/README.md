## S1 원문 단위 (`experiments/stage4_dialogue_units.py`)
- Phase 2 정제 대화의 발화를 `ast_mono_generate.py` 단위 형식으로 쓴다. 이후 생성·판정·수리·타깃 묶기는 Stage 2 와 같다.
- 행 = 원 발화. 정제가 VAD 로 나눈 조각(`<utt_id>#n`)은 같은 화자의 원 발화로 다시 묶는다. 행 id = `<conv_id>|<화자>|<utt_id 앞부분>`.
- 단어 시각 = 정렬 토큰. `" " + text` 를 Qwen3-ASR 토크나이저로 다시 토큰화해 id 를 대조하고, offset 으로 토큰을 단어에 묶는다.
- 원문 = `raw` 를 단어 시각에 문자 정렬한 것(실패하면 정규화 text 단어).
- 일반 단위(`stage4-dlg-units-v1`, 격리 발화 제외, held-out 포함):

  | 언어 | shard | 행 | 단위 | 단어 |
  |---|---:|---:|---:|---:|
  | 영어(otoSpeech) | 43 | 107,696 | 140,038 | 1,050,943 |
  | 한국어(AI Hub 3) | 104 | 549,978 | 557,109 | 2,577,700 |
  | 독일어(KEC·ZTC·NSC) | 32 | 131,355 | 139,729 | 800,107 |

  - 다시 토큰화 실패 0. 원문이 `raw` 가 아닌 행: 한국어 9, 영어 289(0.3 %), 독일어 12.
- 되살린 격리 발화 단위(`stage4-dlg-units-revive-v1`, `--revive-dir phase2/revive-asr-v2`): 한국어 392,166 행·1,686,473 단어(68 shard), 독일어 28,839 행·119,446 단어(5 shard)
  - 원문이 의심스러워 그 번역은 학습에서 입력 문맥으로만 쓴다(label −100). 번역이 없으면 번역 모드에서 한국어 행의 약 42 % 가 빠져 태그·`<EOT>` 구조가 끊긴다.

## S2 네 흐름 시퀀스 (`vapasr/data/cst_dialogue.py`)
- **prefix:** `language <SPK_A>{L} <SPK_B>{L}\ntranslate <SPK_A>{T} <SPK_B>{T}<asr_text><DELAY_d>`. 목표 언어 T 는 한·독 → 영, 영 → 독·한(무작위). 학습 창은 `ast_frac` 확률로 번역 모드, 나머지는 Stage 3 형식이다.
- **흐름:** 0·1 = 슬롯 A·B 전사, 2·3 = 그 번역. 같은 언어 두 슬롯은 창 안에서 먼저 말한 사람이 A 다(Stage 3 와 같다).
- **청크:** 번역 토큰 = stable prefix 확정 시각. 청크 k = ⌊t/0.08⌋ + δ, 청크 안은 (시각, 흐름) — 같은 시각이면 전사가 먼저다(Stage 2 와 같다).
- **태그:** 구간(슬롯, 전사|번역)이 바뀔 때만 단다. 전사 → `<SPK_x>`, 같은 슬롯 전사 바로 뒤 번역 → `<TRANS>`, 그 밖의 번역 → `<SPK_x><TRANS>`.
- **`<EOT>`:** episode 의 마지막 행에 번역이 있으면 번역 흐름, 없으면 전사 흐름에 둔다.
  - 청크는 Stage 3 규칙 그대로다(max(꼬리 청크, ⌊(끝 + 0.24)/0.08⌋)).
  - 어느 흐름이든 그 episode 의 전사·번역 꼬리 중 나중 것 바로 뒤에 온다(`eot_after_tails`).
  - 화자 수준이다. 문맥 슬롯이 같으면 태그 없이, 다르면 `<SPK_x>` 를 열고 낸다.
  - soft label 위치는 Stage 3 규칙이다. 단 `<EOT>` 바로 뒤가 `<TRANS>` 면 태그는 어차피 필요했으므로 결정 위치는 `<EOT>` 다.
- **행과 episode:** 번역 토큰은 확정 시각이 든 episode 하나에만 준다. 행이 episode 여럿에 걸칠 때 두 번 넣지 않기 위해서다.
  - 확정 시각은 행 조각 구간으로 자른다(`clamp_to_spans`). 정렬 토큰이 조각 시작보다 앞서면 전사는 시작으로 당겨지는데, 번역만 앞서 나가지 않게 하려는 것이다. 조각 사이 쉼이면 다음 조각 시작으로 간다.
- **label −100:**
  - 입력, 전사 없는 음성 청크(Stage 3 마스크)
  - 되살린 전사와 그 방출 청크의 `<NEXT_AUDIO>`(Stage 3 revive)
  - 되살린 행의 번역(입력만)과 그것을 여는 태그
  - 번역 없는 행(판정 탈락 = miss, 창 시작 전에 시작한 행 = cut)의 방출 청크의 태그·`<NEXT_AUDIO>`·`<EOT>`
  - 마지막 행에 번역이 없는 episode 의 `<EOT>`
- **검사(`problems_of4`):** 네 흐름 다시 읽기(흐름별 토큰·슬롯별 `<EOT>` 수), 태그 규칙, `<EOT>` 가 꼬리 뒤인가, 입력만 원소의 label, soft 결정 위치
- **테스트:** `tests/test_cst_dialogue.py` 28 개 통과(로컬·mxc). Stage 3 형식은 그대로다(번역을 줘도 tgt·rng 가 없으면 Stage 3 시퀀스와 같다).

## S2 dry-run (`experiments/cst_stage4_dryrun.py`, `dry_pilot.sh`)
- 시험 타깃, 번역된 대화의 창만(`--only-translated`), revive v2, 맞장구 1.0 s·3 토큰
- 창마다 목표 언어별로 δ 하나를 골라 검사했다. 같은 창·δ 의 Stage 3 시퀀스와 비교했다.
- **1 차(`dry-pilot1.json`):** 검사 문제 0. 디코드한 예에서 두 가지를 찾았다.
  1. 번역 토큰이 그 원문 단어의 전사보다 먼저 나왔다(`Ich <SPK_A> i`). 원인: 전사 시각은 발화 구간으로 자르는데 번역은 episode 구간으로만 잘랐다.
  2. 번역이 마지막 원문 단어보다 먼저 끝나면 `<EOT>` 가 그 화자의 마지막 전사 단어보다 앞에 왔다. 원인: `build_interleaved_events` 는 같은 흐름의 앞 원소만 기다린다.
  - 길이 추정도 11 창에서 실제보다 1 % 작았다.
  - 고침: `clamp_to_spans`, `eot_after_tails` + 검사 `eot_before_tail`, 길이 추정에 번역 토큰의 1/4 을 태그 몫으로 더함

## S5 학습 스크립트 (`experiments/stage3_train.py`)
- `--dlg-trans <타깃>`(반복·쉼표·@목록): 대화 셋을 `--dlg-ast-frac`(기본 0.5) 확률로 번역 모드로 낸다.
- `--dlg-trans-input <되살림 타깃>`: 되살린 행의 번역(입력만, `--revive-dir` 과 함께)
- 학습 전 검사에 번역 모드(목표 언어마다)를 더했다. 로그에 `tr_per_dlg_step` 을 남긴다.
- 지문에 `dlg_trans`·`dlg_trans_input`·`dlg_ast_frac` 을 넣는다. 끄면 키가 없어 Stage 3 run 의 재개 지문은 그대로다.
