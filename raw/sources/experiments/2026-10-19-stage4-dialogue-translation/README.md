## S1 원문 단위 (`experiments/stage4_dialogue_units.py`)

## S2 네 흐름 시퀀스 (`vapasr/data/cst_dialogue.py`)
- **prefix:** `language <SPK_A>{L} <SPK_B>{L}\ntranslate <SPK_A>{T} <SPK_B>{T}<asr_text><DELAY_d>`. 목표 언어 T 는 한·독 → 영, 영 → 독·한(무작위). 학습 창은 `ast_frac` 확률로 번역 모드, 나머지는 Stage 3 형식이다.
- **흐름:** 0·1 = 슬롯 A·B 전사, 2·3 = 그 번역. 같은 언어 두 슬롯은 창 안에서 먼저 말한 사람이 A 다(Stage 3 와 같다).
- **청크:** 번역 토큰 = stable prefix 확정 시각. 청크 k = ⌊t/0.08⌋ + δ, 청크 안은 (시각, 흐름) — 같은 시각이면 전사가 먼저다(Stage 2 와 같다).
- **태그:** 구간(슬롯, 전사|번역)이 바뀔 때만 단다. 전사 → `<SPK_x>`, 같은 슬롯 전사 바로 뒤 번역 → `<TRANS>`, 그 밖의 번역 → `<SPK_x><TRANS>`.
- **`<EOT>`:** episode 의 마지막 행에 번역이 있으면 번역 흐름, 없으면 전사 흐름에 둔다.
  - 청크는 Stage 3 규칙 그대로다(max(꼬리 청크, ⌊(끝 + 0.24)/0.08⌋)).
  - 어느 흐름이든 그 episode 의 전사·번역 꼬리 중 나중 것 바로 뒤에 온다(`eot_after_tails`).
  - 화자 수준이다. 문맥 슬롯이 같으면 태그 없이, 다르면 `<SPK_x>` 를 열고 낸다.
  - soft label 위치는 Stage 3 규칙이다. 단 `<EOT>` 바로 뒤가 `<TRANS>` 면 태그는 어차피 필요했으므로 결정 위치는 `<EOT>` 다.
- **행과 episode:** 번역 토큰은 확정 시각이 든 episode 하나에만 준다. 행이 episode 여럿에 걸칠 때 두 번 넣지 않기 위해서다.
  - 확정 시각은 행 조각 구간으로 자른다(`clamp_to_spans`). 정렬 토큰이 조각 시작보다 앞서면 전사는 시작으로 당겨지는데, 번역만 앞서 나가지 않게 하려는 것이다. 조각 사이 쉼이면 다음 조각 시작으로 간다.
- **label −100:**
  - 입력, 전사 없는 음성 청크(Stage 3 마스크)
  - 되살린 전사와 그 방출 청크의 `<NEXT_AUDIO>`(Stage 3 revive)
  - 되살린 행의 번역(입력만)과 그것을 여는 태그
  - 번역 없는 행(판정 탈락 = miss, 창 시작 전에 시작한 행 = cut)의 방출 청크의 태그·`<NEXT_AUDIO>`·`<EOT>`
  - 마지막 행에 번역이 없는 episode 의 `<EOT>`
- **검사(`problems_of4`):** 네 흐름 다시 읽기(흐름별 토큰·슬롯별 `<EOT>` 수), 태그 규칙, `<EOT>` 가 꼬리 뒤인가, 입력만 원소의 label, soft 결정 위치
- **테스트:** `tests/test_cst_dialogue.py` 28 개 통과(로컬·mxc). Stage 3 형식은 그대로다(번역을 줘도 tgt·rng 가 없으면 Stage 3 시퀀스와 같다).

## S3 교차 언어 합성 대화 (`experiments/sim_build_dialogues.py --lang2`, `vapasr/data/sim_dialogue.py`)
- 화자 a 는 `--lang` 풀, 화자 b 는 `--lang2` 풀에서 고른다. 이름은 `sim_<l1>-<l2>`, `Dialogue.lang = '<L1>+<L2>'`, `meta.spk_lang` 에 화자별 언어를 둔다.
- 번역(`--trans`): 발화 Unit 이 번역 토큰을 들고 다닌다. 토큰과 같은 규칙으로 나누고(`split_unit`) 놓는다(`synth_session`).
  - words 행: Stage 2 타깃(행 id = words 행 id). Stage 2 번역 단위는 구간을 넘지 않아 구간 시각으로 나눈다.
  - Phase 2 발화: S1 대화 타깃(행 = 원 utt_id). 조각 구간으로 나눈다(`dialogue_piece_trans`, `clamp_to_spans`).
  - 산출: `<out>/targets-sim_<xx>/<xx>/u-*.jsonl.gz`(`load_ast_targets` 형식, 행 id = `<conv>|<화자>|<utt_id 의 # 앞>`)
- 교차 언어는 상대 언어 번역이 있는 발화만 재료로 쓴다. 시간 구조는 두 언어의 실제 대화에서 함께 잰다.
- **행 무결성(시험 1 차에서 발견):** 한국어는 행 끝에서 번역이 몰아 확정된다. 그래서 세션이 행 중간 조각에서 시작하면 앞 조각의 번역까지 붙어 나왔다(`보자 <TRANS> That's all I have to say, so see you next time.`).
  - 고침: 이어지는 조각(`Unit.cont`)은 세션 시작·맞장구로 쓰지 않는다. 조각이 빠진 행은 번역을 떼어 낸다.
  - 번역 토큰이 하나도 없는 조각은 빈 번역 행으로 남긴다(번역 없음 = miss 와 구별).
- `--heldout`: 평가 셋용. held-out 대화만 쓰고 words 는 쓰지 않는다.
- **데이터셋(`CstDialogueDataset`):** `meta.spk_lang` 에 두 언어가 있으면 슬롯을 언어로 고정한다. 어느 언어를 A 로 둘지는 학습 rng, 평가·점검은 창 id 해시로 정한다.
  - prefix 예: `language <SPK_A>English <SPK_B>Korean\ntranslate <SPK_A>Korean <SPK_B>English`
  - 번역 모드 목표 'xl' 은 각 슬롯이 상대 언어로 번역한다는 뜻이다.
- **시험(`sim_xl_test.sh` 를 고친 2 차, KO↔EN 24 세션):** 한국어 = AI Hub 시험 대화(S1 ko→en), 영어 = otoSpeech 시험 대화(S1 en→ko) + words 3 %(Stage 2 en→ko)
  - 실패 0, 0.44 h, 발화 693 개 모두 번역 행이 있다(행 676, 번역 토큰 6,975). 겹침 4.5 %, 분당 교대 9.4(`sim-xl-test.stats.json`)
  - dry-run 50 창 문제 0, 길이 p99 1,365, Stage 3 대비 1.16 배, 번역 없는 행 miss 0·cut 23(`sim-xl-test-dry.json`)

## S4 번역 평가 도구 (`experiments/cst_stage4_eval.py`, `vapasr/data/cst_eval.py`)
- 창: `--split` 이 있으면 held-out 대화(Stage 3 평가와 같은 표본), 없으면 전부(held-out 재료로 만든 합성 평가 셋)
- 목표: 같은 언어는 `tgt_of` 의 목표마다, 교차 언어는 'xl'
- 참조 = 학습 타깃에서 전사 없는 음성 청크를 뺀 것이다. 번역은 참조 번역이 없는 행의 방출 청크도 뺀다. 가설도 같은 규칙으로 버린다.
- 지표:
  - 받아쓰기·귀속: 같은 언어는 slot·cp·agn, 교차 언어는 슬롯별(언어별) 오류
  - `<EOT>`: Stage 3 와 같다. 합성 셋은 참조가 없어 뺀다.
  - 번역: 창·슬롯이 한 분절인 코퍼스 BLEU·chrF(목표 한국어는 BLEU 글자 토큰화)
  - 번역 지연: 일치 단어의 (가설 − 학습 타깃) 방출 시각 중앙값. 빈 번역 비율도 낸다.
- **오라클(`--oracle`, 정답 시퀀스를 출력으로):** 합성 KO↔EN 영→한·한→영 BLEU·chrF 100, 지연 0, 받아쓰기 오류 0(`eval-oracle-xl2-summary.json`)
  - kec(시험 번역 대화 창) 독→영 100, 세 코퍼스 cp 0, `<EOT>` 재현율 1(`eval-oracle-pilot-summary.json`)
  - 1 차 오라클은 영→한 99.7 이었다. 가설에서만 miss 청크 번역을 버렸기 때문이고, 참조에도 같은 규칙을 넣어 고쳤다.
- **출발점(실제 디코드, `eval-p11-xl-summary.json`):** Stage 3 최종(p11 ck3000)을 번역 prefix 로 합성 KO↔EN 50 창에 그대로 썼다. 대화 번역은 배운 적이 없다.

  | δ | 영어 WER | 한국어 CER | 영→한 BLEU / chrF | 한→영 BLEU / chrF |
  |---|---:|---:|---:|---:|
  | 4 | 76.0 | 104.1 | 16.9 / 15.1 | 8.9 / 21.6 |
  | 10 | 75.2 | 112.4 | 16.5 / 15.3 | 12.6 / 24.2 |

  - 형식을 따르지 못한다(받아쓰기 자리에 다른 말·번역이 섞여 오류가 100 % 를 넘는다). Stage 4 학습이 필요하다는 기준선이다.

### TAXI 어댑터 (`experiments/cst_stage4_taxi.py`, `taxi_p11.sh`·`taxi_p11_asronly.sh`)
- CST-Bench-TAXI natural(실제 독↔영 전화 대화, `cstbench render` 의 세션 mono 혼합 16 kHz, 86 세션·0.74 h, 세션 길이 중앙 29 s·최대 72 s)
- 40 s 넘는 세션은 턴 사이 쉼 가운데에서 나눠 디코드한다(109 창). 슬롯은 데이터셋과 같은 규칙(언어 이름순 + 세션 id 해시)이다.
- 번역 단어를 cstbench 가설 형식(`{session, lang, t, text}`)으로 쓰고 cstbench 채점기(재분절 → BLEU·chrF·StreamLAAL·끝 지연·빈 턴)로 잰다.
- 받아쓰기는 세션·언어마다 이어 붙인 참조 대 그 언어 슬롯(WER), 슬롯 순열을 허용한 WER(cp)도 낸다.
- TAXI 전사·번역은 재배포 금지라 hyp·asr 은 mxc(`results/stage4-taxi-*`)에만 두고 보고서(집계)만 가져왔다.
- **출발점(Stage 3 최종 p11 ck3000 그대로):**

  | 설정 | 독→영 BLEU / chrF | 영→독 BLEU / chrF | StreamLAAL 중앙(독→영·영→독) | 빈 턴(독→영·영→독) | 받아쓰기 WER 영·독 / cp |
  |---|---:|---:|---:|---:|---:|
  | 번역 prefix δ4 | 3.6 / 15.6 | 15.8 / 34.2 | 1.04 · 0.91 s | 152/349 · 69/291 | 102.3 · 96.2 / 93.3 |
  | 번역 prefix δ10 | 3.7 / 15.8 | 18.0 / 35.7 | 1.56 · 1.37 s | 155/349 · 69/291 | 102.2 · 99.0 / 93.5 |
  | 받아쓰기 prefix δ10 | – | – | – | – | 71.1 · 72.3 / 52.9 |

  - 참고(오프라인 정답 분할 상한, [[output-cst-taxi-offline-baselines-20261005]]): 정답 전사 → Qwen3.8-27B 영→독 48.3·독→영 30.6, Qwen3-ASR-1.7B 경유 42.7·28.1, Qwen3-ASR WER 영 13.8·독 7.3 %
  - 받아쓰기 prefix(번역 줄 없음)로도 슬롯 순열 허용 WER 이 53 % 다. 번역 형식 미학습만이 아니라 8 kHz 전화 음성·교차 언어 대화가 처음이라는 점도 크다.
  - 발화 구간 음량은 −19 dBFS(학습 mono −23 dBFS 근처)라 음량 문제는 아니다.
  - 전화 대역 증강을 Stage 4 학습 후보로 둔다.
