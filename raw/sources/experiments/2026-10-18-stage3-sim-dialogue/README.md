## 배경
- **사용자 제안(2026-10-18):** "Stage 1 혹은 Stage 2 에서 활용한 DB 를 활용해서 문맥이 맞지 않더라도 서로 대화한 것처럼 만들어서 학습시킬 수 있지 않아? 일정 부분도 겹치도록 만들기도 하고." → "그래 합성 대화 구현을 시작해."
- 이미 정해 둔 계획과 같은 방법이다. [[decision-cst-training-stages-and-speaker-slots]] D3 의 'A 갈래: 이어 붙인 실제 발화'와, 할 일로 잡힌 '대화 합성기'다. 원래 Stage 5 용이었는데 Stage 3 에 먼저 쓴다.
- **노리는 것:**
  1. 화자 귀속: 교대·겹침·맞장구가 많은 예를 얼마든지 만든다. 정체 헤드 라벨도 정확하다.
  2. 과적합: 영어·독일어 실제 대화가 적어 4,000 step 동안 같은 창을 15–30 번 반복하던 것을 줄인다.

## 구현
- **`vapasr/data/sim_dialogue.py`:**
  - 재료 `Unit`: 한 화자 발화의 오디오 참조 + 토큰(발화 안 끝 시각) + 화자 키
    - Stage 1·2 words 행(`units_from_words_row`): 화자 키를 아는 세트만 쓴다.
      - LibriSpeech: 화자-장
      - Switchboard: 대화 쪽. utt id 의 소수점 없는 시각을 길이로 맞춰 읽는다.
      - VoxPopuli: 연설
      - CommonVoice: `speaker`
      - 여러 구간 행은 구간별로 나누고 토큰은 시각으로 나눈다.
      - 한국어 행은 replay 가 학습 때 KO 정규화를 거치므로 쓰지 않는다.
      - YODAS 는 한 영상에 여러 화자가 섞일 수 있어 뺐다.
    - Phase 2 정제 대화(`units_from_dialogue`): 학습 분할의 전사 감독 발화만 쓴다. 화자 채널(또는 조각)에서 그 구간을 쓴다.
  - **사람 id(`person_ids`):** 다른 대화에서 온 두 화자가 같은 사람이 아니게 한다.
    - AI Hub: 대화 id 의 화자 번호(예 `6450G2A5`) — 채널과의 대응을 몰라 대화의 둘 다
    - KEC·ZTC: 화자 id
    - NSC: 역할 이름이라 세션 이름 `<화자>_<상대역>` 에서 읽는다. 같은 상대역이 여러 세션에 나온다.
  - **시간 구조(`timing_stats`):** 같은 언어 실제 학습 대화의 episode 에서 잰다.
    - 교대 간격(FTO, 음수 = 겹침), 같은 화자 재개 간격, 턴 길이
    - 맞장구(≤ 1 s · ≤ 3 토큰)의 빈도·상대 턴 안 위치
  - **합성(`synth_session`):**
    - 같은 풀에서 다른 사람 둘을 고른다. 각자 발화를 원래 순서로 임의 위치부터 꺼내 턴을 만든다.
    - 재개 확률 `p_hold` 0.3(실제 값 0.53–0.63 은 쉼으로 나뉜 같은 화자 말까지 세서, 합성 턴에 쓰면 교대가 성기다)
    - 교대 간격·재개 간격·턴 길이·맞장구 위치는 실제 분포에서 뽑는다. 맞장구 빈도는 `bc_scale` 1.5 배다.
    - 4 s 보다 긴 발화는 안쪽 쉼에서 구 단위로 나눈다(`split_points`). 앞 조각부터 그 화자의 턴들에 쓴다.
    - 발화 앞뒤 무음은 에너지로 자른다(`speech_span`, 토큰 시각 보호). 간격·겹침이 말소리 기준이 된다.
    - 한 화자는 자기 말과 겹치지 않는다(episode 병합 gap 0.25 s 도 지킨다).
    - 결과 Dialogue 는 화자별 조각 `(path, 대화 시각, src_offset, dur)`(load_channel 규약)과 `meta.mask_eot` 를 가진다.
- **`vapasr/data/cst_dialogue.py`:** `meta.mask_eot` 이면 `<EOT>` 결정 label 을 −100 으로 둔다.
  - `<EOT>` 는 문맥에 남긴다. 빼면 "턴 끝에서 EOT 를 내지 마라" 를 가르치게 된다.
  - 전사·화자 태그·화자 활동은 학습한다.
- **`experiments/sim_build_dialogues.py`:**
  - 풀을 읽고, 시간 구조를 잰다. 세션을 병렬로 합성한다.
  - mono 는 `dialogue_mix` 와 같은 규칙으로 만든다: 화자 발화 구간 RMS → −23 dBFS ± 3 dB, 피크 0.98.
  - 섞은 뒤 잡음·잔향을 둘에 같이 입힌다(잡음 0.5, SNR 10–30, 잔향 0.3). 녹음 조건 차이가 화자 단서가 되지 않게 하려는 것이다.
  - `<out>/mono/sim_<xx>/` 캐시로 저장한다.
- **`experiments/sim_preview.py`:** 세션 몇 개의 오디오·A/B 시간 줄 페이지(로컬 열람용)
- **`experiments/stage3_train.py`:** `--sim-data DIR`, 가중치 키 `sim_ko·sim_en·sim_de`
  - 학습 전 점검에 들어간다. 지문 `sim_data` 는 켤 때만 넣는다.
  - epoch 기준은 실제 대화 셋 그대로다.
  - `slurm/submit-stage3-train.sh --sim-data`
- **테스트(`tests/test_sim_dialogue.py` 9 개):**
  - 행·대화 → Unit, 사람 id, 말소리 구간, 구 나누기, 시간 구조
  - 합성 불변식: 자기 겹침 0, 발화–조각 일치, 토큰 범위, 겹침 생성, 맞장구, 한 화자가 떨어지면 끝냄
  - 조각 되돌리기, Stage 3 데이터셋에서 EOT 가림
  - mxc 에서 `test_cst_dialogue.py` 와 함께 통과
