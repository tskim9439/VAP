# Query Workflow

`AGENTS.md` 의 Query Workflow 를 실행하는 스킬이다. **정본은 `AGENTS.md`** 이다.

## 검색은 임베딩이 아니라 내비게이션이다

임베딩을 생성하거나 외부 검색 API 를 호출하지 않는다. 순서는 고정이다:

1. **`wiki/index.md` 를 먼저 읽는다.** 페이지 카탈로그와 한 줄 요약이 여기 있다.
2. 에이전트 내장 텍스트 검색(grep 등)으로 관련 용어를 찾는다.
3. 관련 페이지와 그 페이지가 인용한 source note 를 읽는다.
4. 위키링크를 따라간다. 인덱스를 두 번 읽는 것은 무료다 — 추측하지 말고 다시 읽는다.

## 답변

- **인용과 함께 답한다.** 위키 페이지와 source note 를 명시한다.
- 위키에 근거가 없으면 없다고 말한다. 지어내지 않는다.
- 페이지 간 모순을 발견하면 답변에 명시하고, 필요하면 `wiki/questions/` 에 항목을 만든다.
- 근거가 약한 주장은 불확실성을 표시한다.

## 산출물 페이지

답이 지속적이거나 재사용 가능하면 `wiki/outputs/` 에 페이지를 만든다
(템플릿: `wiki/templates/output.md`).

1. 브랜치: `scripts/sync-user-branch.sh query <topic>`
2. `summary` frontmatter 를 정확히 채운다 (인덱스가 이것으로 생성된다).
3. 근거가 된 개념·출처 페이지를 위키링크로 연결하고, 가능하면 역링크도 추가한다.
4. `wiki/log/YYYY-MM/YYYY-MM-DD-query-<topic-slug>.md` 로그 샤드를 추가한다.

```markdown
## [YYYY-MM-DD] query | 질문 또는 산출물 제목

- Changed: 생성/변경된 페이지
- Reason: 질문 내용과 산출물이 필요한 이유
- Next: 후속 조사 항목
- By: member-id
```

## 로그를 남기지 않는 경우

페이지 변경이 없는 순수 Q&A 는 로그 샤드도, 브랜치도 필요 없다. 그냥 답하면 된다.

## 원칙

- 답변과 산출물 페이지는 한국어로 쓴다. 고유명사·용어는 원형을 유지한다.
- `wiki/index.md` 를 직접 편집하지 않는다 (생성물).
