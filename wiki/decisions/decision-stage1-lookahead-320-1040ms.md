# 스트리밍 백본: 미리 듣기 320–1,040 ms, 0.6B, 영·한·독 (2026-10-08)

## 맥락
- 모델에 2 화자 구분(diarization)이 들어간다. 사용자는 화자를 가르려면 모델이 충분히 미리 들어야 한다고 보고, 미리 듣기를 최소 320 ms, 최대 약 1 s 로 넉넉히 잡자고 했다.
- 미리 듣는 시간은 두 설정의 합이다.
  - 인코더 청크(Nemotron `att_context [56, r]`): r ∈ {0, 1, 3, 6, 13}, 청크 = (r+1) × 80 ms. 청크 안 프레임마다 0–80r ms 를 미리 본다.
  - 디코더 지연 δ(`<DELAY_δ>`): 모든 프레임에 80δ ms 를 더한다.
  - 최소 = 80δ, 최대 = 80δ + 80r, 평균 = 80δ + 40r. 모두 80 ms 단위라 1,020 ms 는 만들 수 없다(가까운 값 960·1,040).
- 이전 Stage 1 본학습(q17-s1m-r3)은 [56,3] + δ{1,2,3,4,6,8} 로 80–880 ms 였다.
- 같은 평균 지연이면 인코더 lookahead 와 디코더 δ 는 정확도가 비슷했다([[output-stage1-pilot-eval-20261001]] [56,3] 절).

## 선택지
| | 인코더 | 학습 δ | 미리 듣기 | 비고 |
|---|---|---|---|---|
| **A** | [56,3](320 ms 청크) | 4–10 | δ4 320–560 … δ10 800–1,040 ms | `<DELAY_9>`·`<DELAY_10>` 추가 |
| B | [56,3] | 4–8 | 320–880 ms | 토큰 추가 없음, 최대 1 s 미달 |
| C | [56,6](560 ms 청크) | 4–7 | 320–1,040 ms | 인코더 재적응, 출력이 560 ms 마다 몰림 |
| D | [56,13](1,120 ms 청크) | — | δ4 320–1,360 ms | 출력이 1.12 s 마다 몰려 부적합 |

## 결정 (사용자, 2026-10-08)
- **A**: 인코더 [56,3] 고정, 학습 δ = 4,5,6,7,8,9,10 → 미리 듣기 **320–1,040 ms**(1,020 대신 1,040 으로 맞춤).
  - 한 모델로 추론 때 δ 를 골라 운영점을 바꾼다(ASR 위주 δ4–6, 화자·번역 판단 δ8–10).
  - `<DELAY_9>`=151724, `<DELAY_10>`=151725 를 `<SEM_END>`(151723) 뒤에 붙인다. 새 행은 `<DELAY_8>` 복사로 시작하고 decode 에서는 막는다(`vapasr/data/semcommit_tokens.add_delay_tokens`). 151724 는 v0.2 의 `<TURN_END>` 와 같은 id 라 그런 체크포인트에는 붙이지 않는다.
  - 끝 무음은 고정 1 s 를 넣지 않는다. 데이터셋이 항목마다 "마지막 단어 끝 + δ최대 + 2 프레임"까지 배경을 늘려 채운다(평균 0.25–0.66 s; δ1–8 때 0.14–0.52 s).
- **모델 크기: Qwen3-ASR-0.6B thinker**(실시간성 보장). 1.7B 로 같은 설정을 이어 학습하던 job 82730 은 사용자가 취소했다.
  - 이전 파일럿에서 1.7B 는 한국어·final 에서만 유의하게 나았다([[output-stage1-pilot-eval-20261001]]).
- **언어**: 영어·한국어·독일어를 함께 학습한다(독일어는 [[decision-yodas-de-asr-selection]]). 언어별 step 비중은 같다(`--language-schedule balanced`).
- 이번 run 은 지금 형식(프롬프트에 `language {Lang}` 지정, 화자 태그 없음) 그대로다.

## 다음 단계 계획 (사용자 지시, 구현 전)
- 세션 시작 prefix 로 화자와 언어를 짝지어 지정한다. 예: `<SPK_A><EN><SPK_B><DE>`, 한 명이면 `<SPK_B><KO>`.
  - 언어는 항상 지정한다(모델이 언어를 맞히는 auto 학습은 하지 않는다).
  - 출력에는 화자가 바뀔 때 `<SPK_A>`/`<SPK_B>` 만 나오고, 언어는 prefix 의 화자↔언어 대응으로 정해진다.
- 화자 태그는 **최대 2 명(`<SPK_A>`, `<SPK_B>`)**. 어느 사람이 A 인지는 학습 항목마다 무작위로 정한다(위치·언어 편향 방지).
  - 이것은 Phase 2 의 N 화자 일반화([[decision-multi-speaker-scope]], 2026-09-11)를 CST 모델에서는 2 명으로 좁힌다. CST 논문 범위([[decision-cst-paper-v1-scope]])도 2 화자다.
- 언어 토큰 `<EN>`/`<DE>`/`<KO>` 를 새로 붙인다(151726–151728 예정). 두 언어가 섞인 스트림과 2 화자 데이터는 그 단계에서 만든다.

## 결과와 영향
- 학습: job 82738(`slurm/submit-q06-s1m3-d10.sh`, apex 2 노드) — q06-s0 에서 3 epoch, 5,391 step/epoch, 약 1.7 s/step.
- 평가는 δ4·6·8·10 과 final 을 영어(VoxPopuli-AA)·한국어(Kspon)·독일어(YODAS dev, silver)에서 본다.
- 비용: δ 가 커져 꼬리 패딩이 늘어난다(위 수치). 추론 때 평가 꼬리 무음 1.0 s 는 δ10(800 ms)에도 충분하다.

## 재검토
- 0.6B 결과가 나오면(2026-10-09 예정) δ 별 오류율과 1.7B(q17-s1m-r3)·0.6B 파일럿(q06-s1)을 비교해 운영점과 크기를 다시 본다.
  - 2026-10-09 결과([[output-stage1-q06-d10-eval-20261009]]):
    - δ8·δ10 은 δ6 과 오류율이 같다. 넓힌 미리 듣기가 ASR 정확도를 해치지 않는다.
    - 영어는 1.7B 와 같거나 낫다. 한국어는 1.7B 보다 0.6–1.6 %p 나쁘다.
    - 크기 재검토는 사용자 판단으로 남긴다.
- 화자 구분 학습을 붙일 때, 화자 태그만 더 늦게 확정하는 방식(단어는 짧은 δ)도 검토한다.
