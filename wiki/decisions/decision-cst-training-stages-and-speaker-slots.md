# CST 학습 단계와 화자 슬롯 형식 (초안, 2026-10-13)

## 맥락
- **지금까지:**
  - Stage 1 은 스트리밍 ASR 이다(q06-s1m3-d10).
  - Stage 2 는 단일 화자 AST 다. 학습 run q06-s2·s3·s4-ast 가 여기에 속하고, s4 는 진행 중이다.
- **최종 목표(CST 첫 논문 범위, [[decision-cst-paper-v1-scope]]):**
  - 입력: 두 화자가 섞인 mono 입력 하나
  - 모델 출력: 스트리밍 ASR + 2 인 화자 귀속 + 양방향 동시 번역을 하나의 모델이 낸다
  - 상호작용 범위: 끼어들기·맞장구는 제외하고, 턴 끝 겹침(0.2–0.8 s)까지만 다룬다
- **지금 출력 형식(ast-v1, [[decision-ast-monotonic-data]]):**
  - prefix 는 `language <SPK_x>{원천}\ntranslate <SPK_x>{목표}<asr_text>` 이고, x 는 항목마다 A/B 무작위다.
  - 출력은 `<SPK_x>` 로 전사 구간을, `<TRANS>` 로 번역 구간을 연다.
- **사용자 질문(2026-10-13):**
  1. Stage 3(2 인 대화)에서 화자 귀속·ASR·AST 를 한 번에 학습할지, 단계를 나눌지
  2. 마지막 단계의 교차 언어 대화 데이터를 어떻게 만들지
  3. 화자 태그를 모델이 정하게 할지(말한 순서), 언어로 슬롯을 고정할지

## 검토한 선택지

### D1. 단계 구성
| 선택지 | 장점 | 단점 |
|---|---|---|
| Stage 3 에서 화자 귀속 + ASR + AST 를 함께 | 단계 수가 적다. 최종 형식으로 바로 간다 | 결과가 나쁘면 원인(화자 귀속·대화체 ASR·번역)을 가를 수 없다. 대화 데이터의 번역 타깃이 아직 없다 |
| **Stage 3 = 화자 귀속 + ASR, Stage 4 = + 번역** | 원인을 단계별로 가를 수 있다. 단계별 체크포인트가 논문 절제(ablation)가 된다 | 단계가 하나 는다. Stage 3 동안 번역 능력이 약해질 수 있다(아래 장치로 막는다) |

### D2. 화자 슬롯 형식
| 선택지 | 장점 | 단점 |
|---|---|---|
| 말한 순서로 A/B(먼저 말한 사람 = A). 번역 방향은 모델이 판단 | 같은 언어 대화와 형식이 같다 | 대화 내내 목소리를 기억·비교해야 한다(모델 안 화자 메모리). 판단이 셋(화자·언어·방향)이다 |
| **언어로 슬롯 고정: A·B 마다 원천·목표 언어를 선언. 누가 먼저 말하든 그 언어면 그 슬롯** | 판단이 하나로 준다(들리는 언어가 어느 슬롯 언어인가). 방향은 슬롯에 고정된다. Stage 2 형식을 그대로 넓힌다. 모델 안 화자 메모리가 필요 없다 | 같은 언어 대화는 언어로 못 가른다(보조 규칙 필요). 섞어 말하기에서 잘못 붙일 수 있다 |

### D3. 교차 언어 학습 데이터
| 갈래 | 만드는 법 | 장점 | 한계 |
|---|---|---|---|
| **A. 이어 붙인 실제 발화** | 서로 다른 언어의 두 화자 단일 발화를 번갈아 놓는다. 간격·턴 끝 겹침은 실제 대화 분포에서 뽑는다 | 음향이 실제이고 규모가 크다. Stage 2 의 단어 시각·번역 타깃을 그대로 쓴다 | 턴 사이 내용이 이어지지 않는다 |
| **B. 실제 대화의 한쪽 언어 바꾸기** | 실제 2 인 대화에서 한 화자의 턴을 번역해 TTS 로 읽힌다. 원래 턴 타이밍·겹침 구조에 끼운다 | 실제 대화 타이밍과 문맥 흐름이 있다. 한쪽 음향은 실제다 | 다른 쪽이 TTS 다. 번역 길이에 맞춰 간격을 다시 잡아야 한다 |
| **C. 이중 언어 대화 통째 합성** | 병렬 대화 코퍼스나 LLM 이 만든 대화를 화자별 언어로 나눠 공개 TTS 로 합성한다 | 문맥·참조·타이밍을 모두 통제한다 | TTS 음향 차이가 있다. 평가셋(CST-Bench-Syn)과 겹칠 위험이 있다 |
| 실제 교차 언어 대화(TAXI·Verbmobil 등) | 그대로 쓴다 | 진짜 조건이다 | 양이 적고 한↔영은 없다 → 평가 전용 |

## 결정 (제안)
1. **단계:**
   1. Stage 1 ASR(완료)
   2. Stage 2 단일 화자 AST(진행 중)
   3. Stage 3 2 인 같은 언어 대화의 화자 귀속 + ASR
   4. Stage 4 2 인 대화 + 번역
   5. Stage 5 교차 언어 2 인 대화
   - Stage 4·5 는 데이터 준비 상황과 Stage 3 결과를 보고 합칠 수 있다.
2. **Stage 3 의 두 장치:** Stage 4 를 짧게 끝내려고 둔다.
   - Stage 2 의 단일 화자 번역 데이터를 일정 비율 섞어 번역 능력을 유지한다.
   - Stage 3 대화 데이터의 번역 타깃을 학습과 나란히 미리 만든다.
3. **화자 슬롯은 언어로 고정한다.** 예:
   ```
   language <SPK_A>Korean <SPK_B>English
   translate <SPK_A>English <SPK_B>Korean<asr_text>
   ```
   - 누가 먼저 말하든, 한국어로 말하면 `<SPK_A>` 구간이다. 그 번역은 영어다.
   - 두 슬롯이 같은 언어면(Stage 3·4) **먼저 말한 사람이 A** 라는 보조 규칙을 쓴다.
   - 새 특수 토큰은 없다. 단일 화자(Stage 2 형식)는 슬롯 하나만 선언한 특수한 경우로 그대로 둔다.
4. **학습 데이터 규칙:**
   - 어느 언어가 A 인지 무작위로 정한다.
   - 절반 정도는 B 가 먼저 말하게 한다.
   - 한 슬롯만 말하는 구간도 섞는다.
5. **교차 언어 학습 데이터(Stage 5):**
   - A 갈래를 주력(대량)으로 하고, 문맥과 실제 타이밍은 B·C 로 보탠다.
   - 실제 교차 언어 대화(TAXI 등)는 평가에만 쓴다.
   - C 는 CST-Bench-Syn 과 다른 대화 원천·다른 TTS 음성을 쓴다(오염 방지).

## 근거
- **D1:** 다화자 실제 대화의 ASR 은 아직 약하다.
  - Phase 2 lane 평가([[output-phase2-d1-lane-eval]])에서 학습에 쓴 71631 은 CER 18 %, 처음 보는 NIKL 은 12.6 %, AMI 는 39 %, CHiME-6 는 92 % 였다.
  - 화자 귀속·대화체 ASR 을 먼저 따로 확인해야, 번역을 더했을 때의 변화를 해석할 수 있다.
  - 대화체 번역 타깃은 짧은 턴·간투사·말 끊김 때문에 지금 교사 규칙(낭독 단위)을 손봐야 한다. 그 시간을 Stage 3 학습과 겹치게 쓴다.
- **D2:**
  - 언어는 음향에서 뚜렷한 단서이고, 현 모델은 이미 세 언어를 prefix 로 구분해 받아쓴다.
  - Stage 2 가 "prefix 에서 그 언어에 붙은 태그를 낸다"를 A/B 무작위로 이미 학습한다.
  - [[decision-phase2-canonical-lane-plan]] 은 모델 안 화자 메모리를 범위 밖으로 두었다. 말한 순서 방식은 이 결정과 어긋난다.
  - 통역 앱은 보통 시작할 때 두 언어를 정하므로 추가 정보가 필요 없다.
  - 겹칠 때 두 흐름의 언어가 다르다는 점이 섞인 소리에서 두 흐름을 가르는 단서가 된다.
- **D3:**
  - 실제 교차 언어 대화는 양이 적다([[task-cst-data-access]]).
  - A 갈래는 Stage 2 자산(행 단위 번역 타깃 약 639 만 행, 단어 시각)을 바로 쓰므로 비용이 가장 작다.
  - A 가 못 주는 문맥·자연 타이밍은 B·C 가 보탠다.

## 결과 / 파급
- **필요한 작업:**
  - prefix 를 두 슬롯 선언으로 넓힌다(`vapasr/data/ast_dataset.ast_head_text` 와 평가 prefix).
  - 대화용 교사 번역(턴 단위, 간투사·말 끊김 규칙)과 그 품질 검사를 만든다.
  - A 갈래용 대화 합성기를 만든다(간격·겹침 분포, 두 화자 발화 배치, 시각 라벨).
  - B·C 갈래는 TTS 엔진과 음성을 고른다(CST-Bench-Syn S0 파일럿 결과를 공유).
  - Stage 3 평가 지표를 정한다: 화자 귀속 오류율(cpWER·tcpWER 계열), 턴 전환 시각.
- **배제하는 것:**
  - 모델 안 장기 화자 메모리(같은 언어 대화에서 오래 뒤 다시 나온 화자는 외부 재매핑)
  - CST 트랙에서 3 인 이상
  - [[decision-multi-speaker-scope]] 의 N 화자 일반화는 Phase 2(스트리밍 화자 분리) 트랙의 결정으로 남는다.
- **단계 번호:**
  - [[output-staged-training-plan-20261001]] 의 Stage 2(`<SEM_END>`)와 번호가 다르다. 이 결정이 받아들여지면 그 문서의 단계 번호는 이 결정으로 대체된다.
  - `<SEM_END>`(의미 완결) 학습을 어느 단계에 둘지는 열린 질문이다.
  - 학습 run 이름 q06-s2·s3·s4-ast 의 's' 는 Stage 2 안의 반복 번호다. Stage 번호와 헷갈리지 않게, 앞으로 run 이름에는 단계와 반복을 함께 적는다(예: `q06-st3-r1`).

## 열린 질문
- **Stage 3 원천:**
  - 한국어: 71631·NIKL 등
  - 영어: Switchboard·AMI 등
  - 독일어: 2 인 대화 실데이터가 거의 없다(Verbmobil 확보 여부에 따라 A·C 갈래로 보충)
- Stage 2 데이터를 Stage 3 에 섞는 비율
- Stage 4 와 5 를 합칠지(Stage 3 결과를 보고)
- A·B·C 갈래의 비율과 규모
- 섞어 말하기(한 화자가 상대 언어 단어를 쓰는 경우) 예를 언제 넣을지. CST 첫 논문 범위 밖이다.
- `<SEM_END>` 학습 위치
