# E14 — 비귀속 칸(X) + 전문가 확률 활동 (2026-11-03)

- 요청
  - 사용자 "N3D 가 놓친 말을 받아쓰도록 게이트를 고칠 방법을 찾아줘", "결과 나오면 바로 디코드 실험까지 진행해줘".
  - 학습 쪽 후보 셋 중 사용자 선택: 2 번(비귀속 칸)에 "가능하면 1 번(활동 입력을 N3D 확률값으로, 낮은 임계로 게이트)도 함께 넣는 것".
- 한 줄: 라운드마다 슬롯 칸 뒤에 X 칸을 하나 두어, 태그가 닫힌 슬롯의 말을 X 칸이 받아쓴다. 단어는 출력 뒤 N3D 확률(임계 아래 포함)로 슬롯에 붙인다.

## 1. 근거
- 게이트 진단([[output-e13-gate-trans-20261102]] 7 절): E13 회의 통째에서 태그가 닫혀 있던 참조 단어가 IHM-mix eval 3.6 %다. E13 은 그중 약 17 % 만 받아썼다. agn 손해(+2.45)와 맞는다.
- 학습 게이트는 정답 활동이고 활동 입력은 90 % 가 N3D 다. 그래서 E13 은 "열린 태그 + 활동 0" 을 "N3D 가 놓친 말이 있다"로 배웠다.
- 추론 게이트만 넓힌 판(재학습 없음, 묶음 `q17-e13-gate`)은 실패했다. 열린 태그에 다른 화자의 말을 쓴다.
  - `gt0.3`(99709 — 게이트만 확률 > 0.3, 68 회의 끝, 표준): eval 24.39 / 31.33 → 25.99 / 32.82, dev 23.06 / 28.09 → 23.82 / 30.23, Whisper agn eval 23.09 → 23.54.
    받아쓴 단어 몫은 78.2 → 78.3 % 로 거의 그대로이고 LLM DER 헛검출이 6.0 → 10.4 로 늘었다(IHM-mix eval). 재귀속을 얹어도 E13 보다 나쁘다(24.30 / 30.76).
  - `gl0`(99710 — 게이트 끔): 30/68 회의에서 cp 73–79 로 무너져 사용자가 취소했다(14:14). 가설 단어가 참조보다 8 % 많다(같은 말을 여러 슬롯에).
  - 스모크(SDM 창 8 개): 게이트를 넓힐수록 LLM DER 놓침은 14.9 → 12.1 → 9.3 으로 줄고, 헛검출은 2.6 → 5.7 → 40.3 으로 늘었다.
- 1 번의 "낮은 임계 게이트를 학습에서도"는 N3D 출력으로 학습 시퀀스를 만들어야 한다. 시퀀스는 데이터 worker(CPU)에서 만드는데, N3D 를 CPU 로 돌리면 너무 느리다.
  - 측정(서버 호스트 CPU, AMI 60 s 창): 청크 16 은 스레드 1 에 34.9 s · 4 에 13.3 s, 청크 4 는 132.8 s · 49.8 s 다. 학습 한 step 은 3.6 s 이고 GPU 마다 창이 여럿이다.
  - GPU 에서 N3D 를 먼저 돌리고 시퀀스를 만들려면 학습 루프(Trainer 의 배치·packing)를 크게 고쳐야 한다. 이번에는 하지 않았다.
- 그래서 1 번은 두 가지로 넣었다. 활동 입력은 확률 그대로 쓴다(학습·추론 같다). "약한 근거로 화자를 정한다"는 부분은 게이트가 아니라 X 단어의 슬롯 귀속에서 쓴다.

## 2. 형식
```
청크 k: [오디오 k] [<SPK_A>] (<ONSET>) (so) ■ [<SPK_5>=X] (yeah) ■      ← C 는 N3D 가 놓쳐 태그가 없다 — C 의 말은 X 칸이 낸다
청크 k: [오디오 k] [<SPK_5>=X] ■                                       ← 아무 슬롯도 안 열린 라운드도 X 칸은 있다
```
- X 칸은 정해진 입력이다(예약 토큰 `<SPK_5>` — 새 어휘 없음, 처음 켤 때 슬롯 태그 넷의 평균으로 시작). 활동 벡터를 더하지 않는다.
- 슬롯 칸이 열리는 규칙은 E13 디코더 그대로다. 최근 12 청크 활동 창이 열렸거나, 그 슬롯이 연 말(<ONSET> 수 > <EOT> 수)이 있을 때다.
- 학습 시퀀스에서 닫힌 칸에 걸린 정답 원소(`route_closed`)
  - 글자는 같은 라운드의 X 칸으로 옮긴다.
  - `<ONSET>` 은 그 말이 끝나기 전에 활동으로 처음 열리는 라운드로 미룬다(그 칸 맨 앞).
  - 끝까지 안 열린 말은 `<ONSET>`·`<EOT>` 를 뺀다. 창 앞에서 시작해 한 번도 안 열린 말의 `<EOT>` 도 뺀다.
  - 닫힌 칸의 번역 원소는 뺀다. X 칸에는 번역 칸이 없다.
- 가림: X 글자 label 은 원래 슬롯의 가림(전사 없는 음성·되살린 발화)을 따른다. X 칸 멈춤은 닫힌 슬롯에 그런 구간이 있는 라운드면 가린다.

## 3. 학습 게이트 — N3D 놓침 흉내
- 데이터 단계에서 정답 활동에 놓침을 흉내 낸다(`sim_miss`, 학습 rng 만). 창 안 말마다 다음 확률로 적용한다.
  - 1 s 보다 짧은 말: `--miss-short`(0.3) 확률로 통째로 뺀다.
  - 그 밖 말: `--miss-drop`(0.1) 확률로 통째로 뺀다.
  - 남은 말: `--miss-late`(0.3) 확률로 앞 U(0.3, min(2.0, 말 길이/2)) s 를 뺀다.
- 게이트는 놓침을 뺀 활동으로 연다. 헛 구간(`--gate-fa 0.1`)은 E13 그대로다.
- 같은 놓침 프레임(`act_miss`)을 활동 입력에서도 지운다. 흔든 정답 입력은 데이터 단계에서, N3D 입력은 forward 에서 정답 슬롯 자리로 맞춘 뒤 지운다. 추론의 N3D 놓침과 같은 모양이 된다.
- 평가·오라클(rng 없음)은 놓침이 없다. 그때 시퀀스는 E13 + 라운드마다 X 칸이고, 출력·label 은 E13 과 같다(시험).

## 4. 확률 활동과 X 귀속
- `--n3d-soft`(`config.n3d_soft`): 전문가 활동을 0/1 대신 확률 그대로 태그·오디오 활동 주입에 쓴다. 게이트는 디코더가 > 0.5 로 연다.
- X 단어 → 슬롯(`attribute_x`)
  - 단어 오디오 프레임 f = 방출 청크 − 1 − δ 다.
  - 창 [f − 3, f + 1] 의 슬롯 확률 평균이 가장 큰 슬롯에 붙인다(임계 아래 확률도 쓴다).
  - 모두 0.05 아래면 f 앞에서 마지막으로 활성이던 슬롯, 그것도 없으면 0 에 붙인다.
  - 고른 슬롯을 원출력(`x_slots`)에 남겨, 디코드 없는 재채점도 같은 귀속을 쓴다.
- 놓친 단어를 되찾으면 agn 은 바로 준다. cpWER 은 되찾은 단어를 절반 넘게 맞는 슬롯에 붙여야 준다. 놓친 단어는 오류 1 개(삭제), 잘못 붙인 단어는 2 개(삭제 + 삽입)이기 때문이다.

## 6. 남은 것
- dry-run 결과, GPU 스모크(호스트 GPU 가 비면), 사용자 제출.
- 평가: AMI 회의 통째 표준 cp·agn·X 몫·귀속 정확도를 E13·E11 + 재귀속·외부 기준과 비교하고, 대화 번역을 E13 과 견준다.
- 걸리는 점
  - 흉내 낸 놓침은 아무 말에서나 무작위로 고른다. N3D 의 실제 놓침은 작은 목소리·겹침·짧은 맞장구에 몰려 있다. X 칸이 실제 놓침을 얼마나 잡는지는 평가로 본다.
  - 학습에서 X 로 가는 글자는 15 % 안팎으로 어림했다(추론 실제 몫 1–4 % 보다 많다). X 가 열린 슬롯의 말을 겹쳐 쓰는지 평가의 가설/참조 단어 수로 확인한다.
