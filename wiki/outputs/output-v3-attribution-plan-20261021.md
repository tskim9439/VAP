# V3 — 화자 귀속 보정 (2026-10-21)

사용자: "화자 귀속 문제를 완화해서 VibeVoice 에 비해 TAXI 에서 우위를 점하고 싶은데, 최근 연구들을 조사하고 문제를 완화할 수 있는 방안은 모색해. 그래서 이를 적용한 모델이나 기법을 V3 로 명명해서 적용해줘." 이어 "기존의 방식에서의 문제점 등도 함께 검토하고 발전시킬 수 있는 점이 있으면 개선하고". 원자료·스크립트·설계 명세는 [[2026-10-21-v3-attribution]] 에 있다.

## 진단
- **TAXI 차이는 전부 화자 귀속이다.** 같은 정규화로 V1(st4-m2a ck2000, 세션 통째) cp 26.4 · agn 18.4 · 귀속 몫 8.0, VibeVoice 스트리밍 20.5 · 20.1 · 0.4. 받아쓰기는 이미 우리가 낫다 → [[output-vibevoice-stream-comparison-20261020]]
- **오류는 턴 시작에서 교대 태그를 내지 않는 것이다.** 틀린 단어의 89 % 가 놓친 교대 뒤에 오고 94 % 가 턴 통째 오류다. 가설 교대 496 대 참조 540, toggle recall 87.4 %(VibeVoice 98.1 %). 턴 안 오교대는 0.3 %, 첫 턴은 86/86 이 맞다.
- 삼킨 턴 단어의 절반은 틀린 슬롯의 언어로 번역된다. 오라클로 슬롯을 바로잡으면 cp 18.3, 번역 누출까지 없애면 약 16(VibeVoice 오프라인 16.8).
- **원인(측정): V1 은 교차 언어 TAXI 에서 <EOT> 를 하나도 내지 않는다.** 교차 언어 학습 창은 합성뿐이고 합성 <EOT> 는 감독하지 않는다. 그런데 teacher forcing 문맥에는 그 <EOT> 가 남아 있고, 번역 모드 교대는 모두 그 뒤에 온다. 모델은 추론에서 오지 않는 단서로 교대를 배웠다.

## 기존 방식의 문제
- 교대 때만 태그를 내므로 놓쳐도 손해가 없다. 그리고 mono 의 슬롯 태그 가중이 1 이다.
- 감독하지 않는 합성 <EOT> 를 문맥에 남긴다(위 불일치).
- 교차 언어 합성 쌍이 늘 서로 다른 코퍼스여서 채널·코퍼스 교대가 곧 화자 교대다. 전화 대역 증강은 두 화자에게 같고, 레벨 차는 ±3 dB 까지다. 턴 타이밍(같은 화자 지속 30 %·겹침·맞장구)도 TAXI(엄격 교대)와 다르다.
- 화자 활동 헤드는 δ 정렬이 아니고, 디코드에는 하드 삽입으로만 쓰였다(손해). 정체 회복 학습은 교차 언어·번역 모드에 닿지 않는다.
- 턴 결정 지표와 TAXI 없이 튜닝할 전화 dev 가 없었다.

## 문헌 (인용 검증 통과분)
- 교대 재현율 가중 손실: Zhao et al., ICASSP 2023 — recall 55.8 → 65.2. 추론 사후확률 키우기: USM-SCD — F1 64.6 → 75.3.
- 단어 수준 결정·짧은 지연: Kanda et al., Interspeech 2022 — 2 단어 지연이 가장 좋다.
- 화자 증거 주입은 화자 목적함수가 있을 때만 효과(Sortformer, JEDIS-LLM). 목적함수 없는 탭(V2-a)은 효과 없음과 맞다.
- VibeVoice 스트리밍은 화자 결정 지연 1.53–2.00 s, 7B, 약 420k h 사전학습이다.

## V3-p1
모든 구성 요소는 기본값이 꺼짐이고, 끄면 기존과 바이트 동일하다(시험으로 확인). 바탕은 V1 = st4-m2a 레시피(2 슬롯·20–40 s 창·2,500 step)이고 기존 st4-m2a 체크포인트가 대조군이다.

| | 내용 | 플래그 |
|---|---|---|
| C5 | 교차 언어 합성 창의 감독 없는 <EOT> 를 문맥에서 뺀다(그 자리 <NEXT_AUDIO> 라벨 −100) | `--eot-drop-synth 1.0 --eot-drop-sets xl` |
| C1 | 교대 태그 손실 가중 3, <EOT> 뒤 머무름 결정 1.5, 결정 통계 로그 | `--change-tag-weight 3 --hold-tag-weight 1.5` |
| C2 | 2 회선 전화 교차 언어 합성 `sim_en-de-tel`(화자별 전화 대역, ±8 dB, 엄격 교대, 10 % 같은 채널) | 빌더 `--phone-per-speaker` 등, 학습 `--set-phone sim_en-de-tel:0` |
| C3 | 디코드 전용 상태 인지 교대 bias(교차 언어만, 다른 슬롯 태그만, 결정 지점별) — dev 에서만 튜닝 | 평가 `--switch-bias eot=…,res=…,wi=…` |
| C4 | TAXI 형식 비-TAXI 전화 dev(`sim-dialogue-xl-tel-eval-v1`)와 턴 결정 지표 | `sim_to_sessions.py`, `cst_attr_turns.py`, score `--turn-metrics` |
| S0 | 놓친 온셋의 토큰 문맥 분류 | `taxi_v3_probe.py --classify-onsets` |

- 학습: R1 `v3-p1` = C1 + C2 + C5, R2 `v3-p1-nodata` = C1 + C5. 같은 seed·step. R1 − R2 = C2 효과, R2 − V1 = C1 + C5 효과.
- 목표(TAXI, 보고 전용): 귀속 몫 ≤ 3, cp < 20.5(VibeVoice 스트리밍), toggle recall ≥ 95 %. 가드: agn, 같은 언어 귀속, EOT, 단일 화자, 번역이 V1 보다 나빠지지 않을 것.
- 미룬 것: 턴 헤더 형식, Switchboard 같은 통화 실제 2 회선, tel 셋 교대 <EOT> 감독, 교차 언어 놓침 회복·on-policy 교정, lookahead, 단어 정렬 슬롯 헤드(화자 라벨 지연은 사용자 결정), 같은 언어 화자 표현 분기.

- **R4(사용자 제안)**: "그냥 프리픽스에서 2 개 언어만 지정하고, 기존 Muse 처럼 첫 화자가 <SPK_1> 로 지정되도록 하고, 어느정도 모델이 어떤 언어인지 판별하도록 학습시켜보는 건 어때?"
  - 교차 언어 창도 창 안 첫 화자가 `<SPK_A>` 다. prefix 는 `language English German\ntranslate auto` 로 두 언어만 적고, 슬롯 언어와 번역 방향은 모델이 소리로 정한다. 같은 언어 창은 그대로다.
  - 기대: 같은 언어 창과 같은 규칙(첫 화자 = A, 교대 = 다른 슬롯)만 배우면 된다. 위험: 긴 세션에서 슬롯 ↔ 언어 짝 유지, 번역 방향을 스스로 정해야 함.
  - 평가: 창마다 슬롯 ↔ 언어 짝을 cpWER 식으로 고르고, 같으면 창 첫 화자 언어를 슬롯 0 에 둔다. 창이 여럿인 세션은 세션 단위 cpWER 보다 조금 너그러우므로 창 수를 함께 적는다.

## 평가 종합과 같은 언어 회귀 (2026-10-21 밤)
- 온셋 분류(TAXI 통째 δ10): 앞 턴이 맞았던 교대 중 놓침 V1 7.8 % → R2 4.0 %. 남은 놓침은 대부분 RESUME(번역 뒤 같은 슬롯으로 받아쓰기 재개)다. ABSORBED·REASSERT 는 0 이다. 남은 귀속 오류는 번역 → 받아쓰기 전환 지점의 슬롯 선택에 몰려 있다.

- **같은 언어 가드 실패**: Stage 3 같은 언어 7 코퍼스 δ10 agn 18.6 → 21.7–26.4. 교대 태그 과잉이 원인이다. aihub71631 에서 태그 3,110 → 7,200–11,900, 빈 교대 117 → 850–2,640, `<SPK_A> 어 <SPK_B> 어 …` 핑퐁과 강제 진행이 나온다. 현재 코드로 V1 을 다시 재면 저장본과 400/400 창이 같아 디코드 코드는 원인이 아니다. 학습 손실은 V1 과 같다(자유 디코드에서만 드러남).
