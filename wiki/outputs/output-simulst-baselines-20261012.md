# 스트리밍 번역 베이스라인 비교 (2026-10-12)

## 조건
- 평가셋: FLEURS 전체와 CoVoST 2 고정 부분집합(4,148 행)이다. 우리 모델 평가와 같은 행이다.
- 입력: 모든 시스템에 원 발화 + 꼬리 무음 1 s 를 넣는다.
- 채점: 같은 BLEU·chrF 를 쓴다. 영→한은 글자 BLEU 다.
- 지연: LAAL(초)이며, 계산 시간을 뺀 오디오 기준이다. 단어 방출 시각 = 그 단어를 낼 때까지 시스템에 들어간 오디오 길이다.
- 원자료: [[2026-10-12-simulst-baselines]]

**우리 지연 보정 (2026-10-12)**
- 처음 표는 우리 방출 시각을 (디코더 step + 1) × 80 ms 로 셌다.
- 그런데 인코더(Nemotron, att_context [56,3], chunked_limited)는 4 프레임 = 320 ms 를 한 청크로 처리한다. 청크 안의 프레임은 청크가 다 들어와야 나온다.
- 그래서 step k 의 시각을 ⌊k/4⌋+1 청크가 다 들어온 때로 옮겼다(`simulst_common.py from-ours --encoder-chunk 4`).
- 결과: 우리 LAAL 이 0.11~0.15 s 늘었다(평균 약 0.12 s). 아래 표는 보정한 값이다.
- 청크 경계(README 의 0.32 s 정의)를 썼으므로 약간 보수적이다. 특징 추출까지 따지면 약 0.06 s 이르다.

**s4 추가 (2026-10-13)**
- q06-s4-ast(CV4 영어 추가) 행을 굵게 더했다. 아래 '결론'은 s3 기준으로 쓴 것이고, s4 변화는 [[output-q06-s4-ast-eval-20261013]] 에 있다.
- 요약: 영→독·영→한이 크게 좋아졌다. FLEURS 영→한 δ10 은 BLEU 29.7(Seamless 30.6), xCOMET 66.2(Seamless 64.9)다. 영→독 δ10 은 Seamless 와 BLEU 4.1, xCOMET 8.4 차이다. 한→영 δ10 은 떨어졌다.

**표 읽는 법**
- 칸은 **BLEU / chrF / LAAL(s)** 이다.
- s3 의 δ 는 대기 설정으로, 작을수록 빨리 낸다. final 은 오디오 전체를 듣고 번역하는 오프라인 기준이다.
- Seamless 의 t 는 내보내기 판단 문턱이다. IWSLT 의 c 는 청크 길이(0.64·0.96 s)다.
- 크기:
  - s3 약 1.2B
  - SeamlessStreaming 2.5B
  - IWSLT26 연결형 약 6B
  - Hibiki-Zero 3B
  - SimulStreaming 약 10.5B(Whisper large-v3 1.55B + EuroLLM-9B)

## 결론
1. **영→X 는 SimulStreaming 과 SeamlessStreaming 이 앞선다.**
   - FLEURS 영→독: SimulStreaming(30.3)·Seamless(28.4~28.9)가 s3 δ10(22.6)보다 6~8 BLEU 높다. 지연도 s3 보다 짧다(2.0~2.2 vs 2.5 s).
   - CoVoST 영→독: Seamless 가 +6.6~7.3, SimulStreaming 이 +2.7 BLEU 다. 지연은 비슷하다(2.0~2.1 s).
   - 영→한: SimulStreaming 34.3, Seamless 30.6~31.9, s3 δ10 26.3 이다.
   - SimulStreaming 은 우리보다 약 9 배 큰 연결형(Whisper + 9B LLM)이다.
2. **독→영은 Seamless 가 BLEU +3.5~5.5 앞서고, s3 가 지연이 0.15~0.5 s 짧다.**
   - SimulStreaming 은 FLEURS 에서 s3 δ10 과 같은 BLEU(28.2), CoVoST 에서 +2.1 이다.
   - FLEURS chrF 는 s3 δ10 과 Seamless 가 같고(59.4), SimulStreaming 이 61.0 으로 가장 높다.
3. **IWSLT26 연결형(약 6B)·Hibiki-Zero(3B)보다는 s3 가 대체로 낫다.**
   - 예: 독→영 FLEURS 에서 s3 δ10 은 1.93 s 에 28.2 다. IWSLT 는 c640 이 1.81 s 에 23.6, c960 이 2.78 s 에 27.6 이다. Hibiki 는 2.95 s 에 22.9 다.
   - 예외 1: FLEURS 영→독 chrF 는 IWSLT 가 높다.
   - 예외 2: 영→한은 IWSLT c640 이 s3 δ10 과 같은 BLEU 를 2.1 s 빨리 낸다.
4. **가장 큰 약점은 영→한 지연이다.** s3 는 LAAL 3.9~4.5 s 다. Seamless(2.7~2.9 s), SimulStreaming(2.7 s), IWSLT c640(2.4 s)보다 1.0~2.1 s 늦다.
5. **한→영은 지표에 따라 갈린다.** BLEU 는 Seamless 보다 3~5 낮지만, chrF 는 높고(48~50 vs 47) 지연은 0.9~1.8 s 짧다.
6. **오프라인 번역 능력은 이미 Seamless 스트리밍 수준이다.** s3 final 은 FLEURS 에서 Seamless 와 같거나 높고, CoVoST 에서는 0.5~2.5 BLEU 낮다.
   - 따라서 격차는 주로 스트리밍 쪽에서 생긴다: 언제 내보낼지 정하는 방식과 짧은 문장의 번역 누락이다.
   - 예: CoVoST 영→독 δ10 에서 2,217 개 중 50 개가 번역 없이 끝난다.

## 우리 모델 실시간성 (RTF, 호스트 측정)
- 조건: 한 스트림(batch 1), fp32(평가와 같은 정밀도), mxc 호스트 H200 에서 FLEURS 4 방향 24 문장 × δ4·δ10 을 쟀다. 원자료: [[2026-10-12-q06-s3-ast-rtf]]
- 실시간 조건: 인코더 청크 320 ms 마다 인코더 1 청크 + 디코더 4 프레임을 320 ms 안에 끝내야 한다.

| 경로 | RTF | 320 ms 청크 계산 p50 / p95 | 320 ms 초과 | 계산 시간 포함 LAAL 증가 |
|---|---|---|---|---|
| 평가 경로(HF eager 디코드) | 0.86~1.05 | 230~270 / 440~510 ms | 11~27 % | +0.5~1.3 s |
| 실시간 경로(CUDA graph 디코드 + NeMo 스트리밍 인코더) | 0.14~0.15 | 36~41 / 75~85 ms | 7,704 개 중 1 개 | +0.05~0.14 s |

- **실시간 경로(`vapasr/hf/realtime.py`)는 실시간으로 돈다.** 평가 경로보다 약 6.5 배 빠르다.
  - 디코더: 고정 KV 캐시와 입력 위치 1·2 개 forward 를 CUDA graph 로 잡았다. `<NEXT_AUDIO>` 는 다음 오디오 위치와 한 forward 로 넣는다.
  - 인코더: NeMo 캐시 재사용 스트리밍 step 을 CUDA graph 로 돌린다. 청크당 약 5 ms 이고, 파일 전체 인코딩과의 차이는 최대 5.7×10⁻⁶ 이다.
- vLLM 은 쓰지 않았다. 실행 중인 요청에 입력을 덧붙여 KV 캐시를 이어 쓰는 API 가 없어, 80 ms 마다 지난 입력 전체를 다시 prefill 해야 하기 때문이다.
- 평가 경로가 느렸던 것은 계산량 때문이 아니었다. GPU 사용률이 약 18 % 였고 bf16 도 빨라지지 않았다. 토큰마다 커널을 하나씩 띄우는 CPU 쪽 비용이 병목이었다.
- 측정 때 호스트 CPU 부하가 매우 컸다(load 200~330 / 96 코어). 전용 노드 측정(`slurm/submit-stream-rtf.sh`, 사용자 제출)으로 다시 확인한다.
- **실시간 경로의 출력은 평가 경로와 토큰까지 같다.** 192 디코드(토큰 14,441 개)를 모두 대조했다. 그래서 위 비교표의 우리 점수가 실시간 경로의 점수다(fp32).
- 위 비교표의 LAAL 은 모든 시스템에서 계산 시간을 뺀 값이다. 베이스라인의 RTF 는 재지 않았다.

## SimulStreaming 실행 기록
- **첫 실행(c1000-ft25)은 무효다.** BLEU 가 0.9~7.9 로 나왔다.
  - 원인: 공식 README 가 권장하는 VAC(Silero VAD)를 끄고 무음까지 Whisper 에 넣었다.
  - 그 결과 첫 1 s 청크에서 없는 말을 지어냈고(예: "Hallo! Ich bin der Chef von Solklingen …"), 끝에서는 같은 문장을 되풀이했다.
- **재실행(c1000-ft25-vac):** VAC 를 켜고 다시 돌렸다. 위 표의 값이다.
  - 2 개 조각은 방향을 바꿀 때 GPU 메모리 부족으로 멈췄다. 끝난 행은 건너뛰고 이어서 마쳤다(7,668 행).
