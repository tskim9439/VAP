# Phase 2 화자 표현: 고정 ID인가, 교대 표식인가

## 결론

**현재 목표가 화자별 전사·재등장 추적·ONSET/EOT라면 두 후보 중 고정 K ID가 더 적합하다.** A/B를 단순 교대 표식으로 바꾸면 학습 부담 일부를 줄일 수 있지만, 세션 내 화자 정체성이라는 요구를 출력 표현에서 없애게 된다. 세 명 겹침만의 문제가 아니다.

다만 고정 K를 계속 키우는 것은 장기 해법이 아니다. 추천 확장 방향은 **소수의 재사용 가능한 전사 채널과, 크기가 변하는 세션 화자 메모리를 분리**하는 것이다. 이는 새로운 모델·상태 관리 실험이며 현재 구조에서 토큰 이름만 바꾸는 작업이 아니다. 구현 복잡성을 고려해 고정 K를 첫 baseline으로 유지하고 필요성이 드러날 때 비교한다.

이 문서는 선택지 분석이다. **정본·registry·수락된 결정은 변경하지 않았고 학습도 실행하지 않았다.** 아래 동적 설계와 실험 수치는 제안이다.

세 번째 후보의 상세 실행안은 [[output-phase2-dynamic-speaker-memory-plan]]에 있다. lane·episode·speaker 3층 분리, SEG_END, 지연 EOT pointer, HF 학습 경로와 단계별 관문을 다룬다. 기존 정본을 자동 대체하지 않는다.

## 1. 화자 수를 세 종류로 구분한다

- **N: 세션 전체 고유 화자 수.** 열 명이 차례로 발언하면 N=10이다.
- **S(t): 그 시각에 실제로 겹쳐 말하는 화자 수.** 위 예에서 대부분 S=1일 수 있다.
- **R: 모델이 동시에 유지하는 전사 채널 수.** 지연 전사·pending 이벤트까지 있으면 필요한 상태 수가 순간 S보다 커질 수 있다.

현재 K는 세션 ID 수를 제한한다. A/B virtual channel은 전사 채널을 두 개로 제한한다. 둘은 같은 용량 제한이 아니다. 또한 A/B를 사용해도 “턴 교대”와 “같은 사람의 재등장”은 별도 판정이다. [[output-phase2-streaming-asr-diarization-plan]] §1·4

## 2. A/B 교대만으로 잃는 정보

아래는 설명용 가상 예시이며 실측 전사가 아니다.

```text
실제 사람:  민수 → 지수 → 민수
교대 표식:    A →   B →   A

실제 사람:  민수 → 지수 → 철수
교대 표식:    A →   B →   A
```

두 대화의 교대 표식이 같다. 따라서 **표식만으로 세 번째 발언자가 처음 사람인지 새 사람인지 복원할 수 없다.** 오디오 기반 식별기를 추가하면 해결 가능하지만, 그 식별기가 사라진 ID 기능을 다시 담당하는 것이다.

세 명의 토큰을 시간순 문자열에 모두 나열하는 것 자체는 가능하다. 불가능한 것은 **두 고정 전사 버퍼에 세 개의 동시에 진행되는 화자 흐름을 충돌 없이 대응**시키는 일이다. `<CHANGE>`만으로는 “직전 화자가 아니다”를 알 뿐 나머지 둘 중 누구인지 모른다. 별도 pointer/ID/경계 메타데이터를 도입하면 표현을 확장한 다른 설계가 된다.

비중첩에서도 재등장 ID가 없다면 화자별 누적 전사, “누가 끝났는가”, 특정 화자의 다음 onset/hazard를 그대로 제공할 수 없다. “현재 발언자가 끝났는가”라는 구간 단위 과제로 범위를 줄일 때만 A/B 교대 단독이 충분할 수 있다.

## 3. 비교

| 기준 | 고정 세션 ID K개 | A/B 교대·2 virtual channels만 | R local channels + 동적 화자 메모리 |
|---|---|---|---|
| 동일 화자 재등장 | 모델이 ID를 유지해야 함 | 표식만으로 복원 불가 | 메모리 매칭으로 복원 |
| 세션 N>K | 표현 상한 초과 | 순차 전사는 가능, 고유 ID는 없음 | 전사 채널과 별개로 메모리 확장 |
| 3중 겹침 귀속 | K≥3이고 학습됐을 때 가능 | 두 버퍼만으로 보장 불가 | R≥3 및 해당 음향 학습 필요 |
| 뒤쪽 ID 희소성 | 도착순 label의 구조적 편향 | 전역 4/5번째 ID 문제 없음 | identity별 별도 분류 행 대신 공유 매칭 가능 |
| 화자별 EOT·future head | 현재 설계와 직접 연결 | 원래 목표를 축소하거나 외부 ID 필요 | 동적 메모리 참조와 head 재설계 필요 |
| 구현 난도 | 현재 계획 중 가장 작음 | 전사만이면 작음, diarization까지면 별도 작업 | 매칭·상태·라벨·배치 처리 난도 큼 |

이는 표현과 설계의 비교다. WER·DER·지연의 우열은 아직 실험하지 않았다.

## 4. 네 번째 이후 학습이 불리한가

**우려는 타당하나 세 가지 원인이 섞여 있다.**

1. **출력 ID 노출 불균형:** 도착순 규약에서 2화자 표본에는 3/4번 positive가 없다. 뒤쪽 token/활동 출력은 positive 감독이 적을 수 있다.
2. **정체성 관리 난도:** 여러 사람을 기억하고 오랜 침묵 후 재등장을 구별하는 과제는 2화자 대화에 부족하다.
3. **음향 난도:** 3중 겹침은 실제로 세 음성의 내용을 분리해 알아들어야 한다. ID 빈도를 균등하게 해도 해결되지 않는다.

공유 encoder/thinker는 대부분의 파라미터를 공유하므로 4번 화자의 ASR를 별도 모델로 처음부터 배우는 것은 아니다. 반대로 2화자 target을 3/4번으로 단순 치환해도 3중 겹침·다자 memory 학습이 새로 생기지는 않는다.

### 고정 K baseline에서 먼저 할 일

- token별 positive 횟수·노출 audio 시간, 세션 N별, 순간 S별, 첫 등장/재등장별 오류를 별도로 집계한다.
- 자연 다자 대화와 긴 재등장 간격을 갖는 carry 창을 명시적으로 샘플링한다. 전체 음향/텍스트 loss가 큰 화자에게만 지배되지 않는지 본다.
- train 화자 조각으로 세션 인원 증가와 3/4중 overlap을 **별개 축**으로 합성한다. 자연 turn label은 붙이지 않는다.
- per-slot activity/future 판별기의 파라미터 공유·slot-conditioned query를 후속 비교한다. token embedding 몇 행의 부족과 memory/음향 실패를 분리한다.
- **도착순 정답을 유지하면서 ID만 무작위로 바꾸면 안 된다.** 동일 오디오 prefix가 설명 없이 다른 정답을 갖게 된다. permutation을 쓰려면 모델이 보는 slot query/memory와 lexical·activity·event 라벨을 일관되게 바꾸고, 추론 시 외부 ID를 별도 정규화하는 다른 계약이 필요하다.

K=8 같은 값은 확정 해법이 아니다. 실제 포함할 세션 N을 보고 정해야 하며, 큰 K를 선언한다고 해당 인원 성능이 확보되지 않는다. 초과 표본을 제외해 평균을 높이거나 마지막 슬롯에 합치지 말고 실패·unknown·coverage를 보고한다.

## 5. 연구에서 확인되는 역할 분리

**t-SOT**는 가상 출력 채널 변경 토큰으로 겹침 전사를 직렬화한다. 기본형은 동시 발화 2개를 다루되 세션의 총 화자 수를 두 명으로 제한하지 않는다. 논문 §2.2는 M개의 채널 선택 토큰으로 일반화하지만, 실험은 최대 2개 동시 발화였다고 명시한다. 채널 선택만으로 화자 수나 전역 정체성을 얻는 방식은 아니다. [원문 §2.1–2.3 및 Appendix A](https://arxiv.org/html/2202.00842v5)

**t-vector**는 t-SOT에 토큰별 화자 임베딩을 추가해 전사와 화자 귀속을 연결한다. 다만 해당 논문의 LibriCSS diarization 실험은 oracle 화자 수를 사용했다. “토큰 임베딩을 붙이면 미지의 인원에서도 온라인 ID가 자동 해결된다”는 근거로 확대하면 안 된다. [원문 §3.2·4.2](https://arxiv.org/pdf/2203.16685)

**Streaming Sortformer**는 도착순 화자 cache를 사용하지만, 확인한 2025 논문 모델은 4개 출력이다. 캐시가 있다는 것만으로 무제한 화자 지원이 되는 것은 아니다. 논문은 5명 이상에서 주요 4명을 추적하는 해석을 제시하며 8명 확장은 후속 과제로 적는다. [원문 §2.1·4·5](https://arxiv.org/html/2507.18446v1)

세 출처의 확인일은 2026-09-14다. 위는 확인한 논문 버전의 내용이며 이후 모델 전체를 포괄하는 최신 성능 서베이는 아니다.

## 6. 장기 후보: 전사 채널과 사람 ID의 분리

다음은 위 역할 분리에서 출발한 **우리 프로젝트용 제안**이며 해당 논문을 그대로 구현한 것이 아니다.

```text
mono → 공유 encoder/thinker
          ├─ lexical + local channel 선택 (예: R=4)
          └─ 선택한 전사/화자에 조건화한 speaker embedding
                          ↓
                 세션 메모리와 공유 매칭 + NEW/UNKNOWN
                          ↓
                 외부 ID speaker_001, 002, …
```

모델이 `<SPK_17>`이라는 희소 분류 행을 배울 필요 없이, “이 표현은 기존 메모리 중 누구인가/새 화자인가”를 같은 함수를 사용해 판단하도록 한다. 외부 ID의 정수 증가는 상태 관리 역할이다. 그렇다고 학습에서 보지 못한 긴 세션·큰 N에 일반화가 보장되지는 않는다. 비교 후보가 늘수록 오매칭·false-new 위험이 커진다.

주의할 구현 조건:

- 같은 혼합 audio hidden 하나를 그대로 speaker embedding으로 쓰면 겹친 사람들을 분리하지 못한다. **토큰/선택된 source에 조건화한** 표현과 감독이 필요하다. token-conditioned 접근은 t-vector를 참고하되 별도 검증한다.
- local channel 재사용은 세션 ID 삭제가 아니다. `channel_id, generation, global_speaker_id` 매핑을 두고 각 pending lexical/event에 소유자를 고정한다. 채널을 다른 사람에게 넘긴 뒤 늦게 나온 EOT가 새 사람을 닫으면 안 된다.
- VAD=0 또는 C-mode EOT를 채널 해제 신호로 그대로 쓰지 않는다. 지연 전사와 수초 뒤 EOT 때문에 **메모리의 unresolved 사건 수와 현재 발화 수가 다르다.** 해제/새로 배정하는 규칙은 causal하게 정의하고 학습과 추론을 맞춰야 한다.
- activity/future/hazard를 계속 고정 K행에 두면 정체성 상한은 남는다. 메모리-conditioned 공유 head 또는 조회 집합을 설계해야 한다. 잠시 조용한 화자의 재개 예측을 위해 현재 활성 local channel만 조회해서도 안 된다.
- 오디오 memory는 관측된 prefix에서만 갱신한다. clean source·정답 화자 수·전체 파일 clustering 결과를 배포 입력으로 주지 않는다. 짧은 발언·처음부터 겹침·낮은 confidence는 provisional/unknown으로 보존한다.
- 메모리 크기·연산량·수명에 운영 상한은 여전히 필요하다. R을 넘어선 실제 겹침은 별도 overflow 과제다. 이를 “무제한 화자 완전 지원”이라고 부르지 않는다.

장점은 **전역 희소 ID와 현재 전사 채널의 결합을 푼다**는 것이다. 대가는 신규 매칭 모듈, memory 오염/재식별, 동적 head, 지연 이벤트 귀속이라는 추가 연구다. “A/B만 쓰면 단순해진다”의 비용 일부가 여기로 이동한다.

## 7. 지금 무엇을 선택할 것인가

1. **즉시 실행:** 현재 고정 K를 비교 기준으로 유지한다. K는 포함 세션 분포로 결정하고 실제 71631·AMI 파이프라인 및 16 fixtures를 먼저 연결한다. 학습 규약을 다시 크게 바꾸어 실물 검증을 미루지 않는다.
2. **진단 분리:** 같은 모델 출력에서 selector를 제거한 인식 오류와 화자 귀속 포함 오류를 모두 측정한다. 단순 전사 향상을 diarization 향상으로 보지 않는다. 공식 cpWER는 virtual lane 그대로가 아니라 실제 화자별 regrouping 뒤에만 비교한다.
3. **확장 실험:** 세션 N을 늘리되 S≤2인 표본과 N=3/4에서 S=3인 표본을 따로 만든다. 전자는 메모리/ID 병목, 후자는 음향/동시 전사 병목을 본다. 동일 학습량·데이터·지연 조건을 유지한다.
4. **구조 비교:** 고정 K vs local R+speaker memory를 비교한다. A/B 교대 단독은 ASR 표현 대조군으로는 유용하지만 화자별 turn-taking을 유지하는 완성 대체안으로 채택하지 않는다.

지표는 ASR 오류, 귀속 오류/DER, 첫 출력 ID switch·재등장 오류, 신규/기존 혼동, unknown·overflow, 이벤트 오귀속, tick/backlog다. oracle ID 매핑 결과는 상한 참고로만 내고 실제 memory 추론 결과와 분리한다. 사후 ID 수정이 있으면 최초 출력 기준과 수정 후 결과를 둘 다 보고한다.

**판단:** 당장 두 선택지 중에서는 고정 K. 세션 화자 수의 구조적 상한을 줄이는 방향은 “A/B 교대로 의미를 버리기”가 아니라 “local 전사 채널 + 공유 화자 표현·동적 메모리”다. 후자의 도입은 실측 병목과 구현 비용을 본 뒤 별도 승인할 사항이다.
