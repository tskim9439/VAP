# Phase 2 정본 계획 비판과 대안

검토 답변 및 반영 결과(2026-09-11): [[output-phase2-critique-response]]. 정본은 v1.1로 개정되었으며 아래 비판은 개정 전 계획에 대한 원래 논점으로 보존한다.

## 질문
[[output-phase2-streaming-asr-diarization-plan]] 은 그대로 실행해도 되는가. 어디가 약하고, 더 나은 해법이 있는가.

## 요약
- **판정: 실행 가능한 좋은 계획이지만 완벽하지 않다.** 계약·관문·평가 규약·실패 가설은 충실하다. 약점은 (1) 겹침 전사의 직렬화 규칙이 필요 이상으로 복잡하고, (2) "의미 기반 turn 예측" 을 뒷받침할 학습 신호가 너무 적으며, (3) 화자 정체성을 붙잡아 줄 명시적 장치가 없고, (4) 사용자 목표 1 번(실시간 ASR 강화)이 계획 밖으로 밀려났다는 점이다.
- 코드에 대한 계획의 주장 3 건은 모두 사실이다(§1).
- 제안 9 건 중 **채택 권고 5 건**(P1 청크 내 화자별 그룹 직렬화, P2 텍스트 전용 완결성 사전학습 + LLM 약라벨 격상, P5 ASR 강화 병렬 트랙, P7 E2 레시피를 초기값으로, P9 MVP 축소 경로 명시), **조건부 4 건**(P3 화자 슬롯 메모리, P4 슬롯 조건 오디오 토큰 2 개, P6 자연형 overlap 합성, P8 turn 헤드 기본 δ=2). 어느 것도 정본의 mono 입력·단일 모델·병렬 헤드 원칙을 바꾸지 않는다.

## 1. 검증한 사실
| 계획의 주장 | 확인 | 위치 |
|---|---|---|
| `<SPK_A/B>` 가 HF 디코드에서 차단돼 있다 | 사실. 억제 토큰 목록에 `<SPK_A>`, `<SPK_B>` 포함 | `vapasr/hf/modeling_vapasr.py:154` |
| 저장 로직이 `encoder_trainable` 이 아니면 인코더를 생략한다 | 사실. E2 를 동결해 저장하면 인코더 가중치가 빠지고 로드 시 원본 `.nemo` 가 붙는다 → 다른 모델 | `modeling_vapasr.py:122-126, 133-140` |
| `assemble_stream` 은 겹치는 입력을 합산하지 않는다 | 사실. `out[o:o+n] = x[:n]` 덮어쓰기 | `vapasr/data/streams.py:84` |

세 번째는 정본이 말한 대로 Phase 2 전용 mixer 로 해결하면 되고, 두 번째는 Q0 에서 "학습 여부" 와 "저장 provenance" 를 분리하는 작은 수정(항상 인코더 저장 + 출처 해시 기록)으로 끝난다.

## 2. 강점 (유지)
- mono 입력·단일 모델·오디오 클럭 병렬 헤드·`h_audio[k]` 의 인과 위치 고정([[output-interleaved-streaming-slm-architecture]] 와 일관).
- A/B 를 세션 내 도착 순서 익명 ID 로 정의하고 전사·활동·VAP 라벨에 같은 permutation 을 강제한 점. PIT 를 청크 단위로 바꾸지 않는 원칙.
- "의미 이해" 를 audio-only / text-ablation / oracle-history 대조군으로만 주장하겠다는 §8.2, 화자 소실 지표, 합성 데이터의 turn 손실 마스킹, 관문을 test 전에 동결하는 규율.
- 실패 가설 표(§11)가 원인 분리 실험까지 적어 둔 점.

## 3. 문제점과 대안 (중요도 순)

### P1. 청크 내 직렬화: 종료 시각 순 교차 → **화자별 그룹화** (채택 권고)
정본 §4.2 는 두 화자 토큰을 종료 시각 순으로 섞는다(`<SPK_A> 그때 <SPK_B> 응 <SPK_A> 내가`). 그러나 청크(80 ms) 안의 순서는 **시간 정보가 없다** — 시간은 청크 인덱스 k 가 이미 준다. 교차 직렬화는 (a) overlap 중 거의 토큰마다 태그가 붙어 구조 토큰이 늘고, (b) BPE 조각 사이에 상대 화자가 끼어 정본 스스로 "원자 단위 유지·버퍼 복원" 이라는 예외 규칙을 추가해야 했다.
**대안**: 청크마다 `[AUDIO_k] <SPK_A> A의 토큰… <SPK_B> B의 토큰… <NEXT_AUDIO>` 로 화자별 블록을 고정 순서(A → B)로 낸다. 태그는 청크당 최대 2 개, 조각 교차 없음, 파서는 "태그 뒤 토큰은 그 화자" 뿐. 정보량은 교차 방식과 같고(청크 내 순서는 어차피 무의미), 직전 청크와 같은 화자가 이어질 때 태그를 생략하는 규칙도 그대로 쓸 수 있다. t-SOT 의 종료 시각 순 직렬화는 프레임 단위 전사기에서 시간을 표현하기 위한 것이었고, 우리는 청크 토큰이 그 역할을 한다.

### P2. "의미 이해" 학습 신호가 너무 적다 → **텍스트 전용 완결성 사전학습 + LLM 약라벨 격상** (채택 권고)
정본 §6.3 은 사람 라벨 500–2,000 경계를 만들고 LLM 자동 라벨은 "후속 약한 라벨 후보" 로 미룬다. 사람 라벨 수천 건은 **평가**에는 충분하지만 헤드를 **학습**시키기엔 부족하고, turn 헤드의 실제 학습 데이터는 자연 대화 ≈350 h 의 VAD 유도 라벨뿐이다. 그러면 Q3 의 H2(LLM 상태가 음향 대조군보다 낫다)가 실패했을 때 "의미 표현이 없어서" 인지 "의미 라벨이 없어서" 인지 가릴 수 없다.
**대안**:
1. **텍스트 전용 사전학습**: NIKL 515 만 발화·71631 332 만 발화·otoSpeech SRT·Switchboard/CallHome 전사에서 "이 prefix 에서 화자가 바뀌는가 / 발화가 완결됐는가" 를 오디오 없이(오디오 자리 마스킹, 텍스트만 인터리브) thinker 위 헤드로 먼저 학습한다. 수백만 경계, GPU 1 시간 규모. 이 헤드를 Q3 초기값으로 쓰면 음향 헤드와 "의미 헤드" 의 기여를 분리해 보고할 수 있다.
2. **LLM 의사라벨을 학습용으로 격상**: [[source-soulx-duplug]] 처럼 큰 LLM 으로 complete/incomplete 를 전사 전체에 매기고, 사람 라벨은 그 정확도 검증(agreement)에만 쓴다. 정본의 "사람 검증을 대체하지 않는다" 원칙은 유지된다 — 역할이 바뀔 뿐이다.

### P3. 화자 정체성 앵커 부재 → **화자 슬롯 메모리 2 개** (조건부: Q1 부터 옵션 구현, Q4 전 결정)
정본은 A/B 유지가 LLM 문맥에만 의존하고, 실패하면 t-vector 보조 손실을 붙이겠다고 한다. 15 분 대화·긴 침묵 뒤 복귀·비슷한 음색에서 태그 반전은 거의 확실히 일어나므로 "실패 후 추가" 는 일정 위험이다.
**대안**: 슬롯 A/B 마다 인코더 특징의 지수이동평균 임베딩을 두고, activity 헤드가 "단독 활동" 으로 판정한 청크에서만 그 슬롯을 갱신한다(인과적, 관측 prefix 만). 매 청크 두 슬롯 임베딩을 adapter 출력에 zero-init gated residual 로 더한다. 파라미터 수십 k, 지연 0, [[decision-mono-input]] 위배 없음. Sortformer 의 도착 순서 슬롯과 같은 정신이고 별도 화자 인코더가 필요 없다. 정본의 t-vector 안보다 구현이 작고 추론 경로에 바로 쓸 수 있다.

### P4. overlap 전사 용량 → **슬롯 조건 오디오 토큰 2 개** (조건부: Q2 관문 실패 시 첫 대안)
청크당 오디오 토큰 1 개(1024 차원)에 두 화자의 음소 정보를 모두 담고, 한 디코더가 두 화자 텍스트를 번갈아 내야 한다. 정본은 실패 시 "multi-output decoder" 를 검토하지만 그것은 구조 변경이 크다.
**대안**: P3 의 슬롯 임베딩을 query 로 인코더 프레임(청크 내 8 프레임 + 좌측 문맥)에 cross-attention pooling 을 걸어 `[AUDIO_k^A][AUDIO_k^B]` 두 토큰을 만든다. 입력은 여전히 mono 이고, 화자별 채널 입력(폐기된 안)과 달리 분리는 임베딩 공간에서 모델이 배운다. 비용은 오디오 토큰 25 Hz(KV 2 배, 15 분 대화 22 k 토큰 — 32 k 컨텍스트 안). 텍스트 블록은 P1 의 A/B 그룹과 자연스럽게 짝이 된다.

### P5. 사용자 목표 1(실시간 ASR 강화)이 계획 밖 → **병렬 트랙 A 명시** (채택 권고)
정본 §10 은 ASR 개선(E3, next_weight, δ)을 "별도 run" 으로 미루고 Phase 2 초기값을 E2 로 고정한다. 초기값 고정은 옳지만, 트랙이 없으면 목표 1 은 Phase 2 종료 때 그대로 남는다.
**대안**: Q1–Q3 와 병렬로 트랙 A 를 둔다. (i) δ=2 정확도: `<NEXT_AUDIO>` 가중 상향·δ 분포 재조정·E3 추가 epoch([[output-stage2-e2-final-eval]] 후속 후보), (ii) 대화체 재가중(71631·NIKL 비율 상향), (iii) 디코더 속도: static KV cache·CUDA graph·MLX 인코더 포팅으로 tick p99 여유 확보, (iv) 잔향·잡음 증강 — Phase 2 mixer 의 RIR 과 같은 코드. **머지 규칙**: 트랙 A 의 체크포인트는 Q3 시작 전 한 번만 Phase 2 초기값으로 승격하고 Q0 평가 pack 을 다시 돌린다(정본 §10 마지막 문단과 일치).

### P6. 합성 overlap 의 분포 → **자연형 overlap 합성** (조건부)
정본 §5.1 은 10–30 % / 30–50 % 균일 스트레스 조건을 둔다. 자연 대화의 overlap 은 [[output-vap-target-pipeline]] 통계대로 **backchannel 이 압도적**(71631 실내 BC 51 k vs INT 6.6 k), 그다음 terminal overlap·interruption 이다. 균일 긴 overlap 은 실전 분포와 달라 Q2 관문(overlap cp 오류 −20 %)이 실전 개선을 대표하지 못할 수 있다.
**대안**: 합성의 70 % 는 자연 유형을 모사한다 — 같은 코퍼스의 실제 맞장구·짧은 발화 뱅크를 상대 발화 꼬리·중간에 얹기(길이 ≤1 s), terminal overlap 0.2–0.5 s. 30 % 만 스트레스. 평가도 유형별(BC / terminal / INT / 장시간)로 나눠 보고한다.

### P7. 학습 레시피 초기값 (채택 권고, 작음)
정본 §7.1 은 thinker 5e-6–1e-5, 인코더 동결 시작·해동 시 1e-6–5e-6 을 "측정 전 탐색 범위" 로 둔다. E2 는 thinker 2e-5·인코더 1e-5 해동에서 붕괴 없이 최선 결과를 냈으므로 **E2 레시피를 초기값, 동결·저 LR 을 대조군**으로 두면 sweep 한 라운드를 아낀다. 겹친 음성의 표현은 인코더가 배워야 하므로 해동이 기본이어야 한다는 근거도 있다([[output-phase2-plan]] §3).

### P8. turn 헤드가 보는 텍스트는 δ 만큼 낡다 (조건부, 작음)
δ=4 면 헤드가 보는 확정 전사는 320 ms 전 것이다. 사람의 −151 ms 를 노리면서 의미 신호가 320 ms 늦으면 불리하다. 정본은 δ=2/4 비교를 약속했으니 **turn 헤드 run 의 기본값을 δ=2** 로 두고, hidden state 가 미방출 단어를 이미 담고 있는지(선형 probe) Q3 초반에 확인하자는 제안이다.

### P9. MVP 축소 경로 부재 (채택 권고)
정본은 Q0–Q4 를 순차로 두지만 시간 부족 시 무엇을 버릴지 없다. 사용자 목표 2·4·5·6(화자 구분·overlap 검출·화자별 전사·2 명 한정)은 **Q1 + Q2 + activity 헤드**만으로 달성되고, 목표 3(의미 기반 turn 예측)만 Q3 에 걸려 있다. 이를 명시하고 Q3 는 VAP 만 → hazard → 의미 ablation 순으로 잘라낼 수 있게 한다.

## 4. 제안 반영 시 단계 변화
| 단계 | 정본 | 변경 |
|---|---|---|
| Q0 | 데이터 계약·평가 pack | + 인코더 저장 provenance 수정, + 텍스트 전용 완결성 사전학습(P2-1), + 자연형 overlap 합성기(P6) |
| Q1 | 비중첩 태그 전사(교차 직렬화, 인코더 동결) | 화자별 그룹 직렬화(P1), E2 레시피(P7), 슬롯 메모리 옵션 구현(P3) |
| Q2 | overlap 전사 | 실패 시 첫 대안 = 슬롯 조건 오디오 토큰 2 개(P4), 유형별 overlap 평가(P6) |
| Q3 | turn 헤드·의미 ablation | 텍스트 사전학습 헤드로 초기화, LLM 약라벨 학습·사람 라벨 검증(P2), 기본 δ=2(P8) |
| 병렬 | — | 트랙 A: ASR 강화(P5) |
| 전체 | — | MVP = Q1+Q2+activity(P9) |

제안을 반영한 단일 실행 문서: [[output-phase2-final-plan]].

## 불확실성
- P1 은 "청크 내 순서가 무의미하다" 는 전제에 선다. δ 조건으로 종료 청크가 같은 두 화자 토큰의 실제 종료 시각 차는 최대 80 ms 이므로 맞지만, 향후 청크를 40 ms 로 줄이면 재검토.
- P2 의 텍스트 전용 사전학습이 음향 헤드로 전이되는지는 근거가 없다(가설). 실패해도 비용은 작다.
- P4 는 인코더 프레임 위 cross-attention 이 mono 에서 화자 분리를 배운다는 가정이며, 겹침이 심한 구간에서는 슬롯이 섞일 수 있다.
- t-SOT·Sortformer·SoulX-Duplug 의 세부는 원문 재확인 없이 인용했다.
