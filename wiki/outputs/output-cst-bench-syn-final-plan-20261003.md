# CST-Bench-Syn 최종 계획 v1.1 (2026-10-03)

> 이 문서는 [[output-cst-bench-synthetic-plan-20261003]] 의 논의(초안 → 사용자 결정 → 약관·비용 조사)를 정리한 **실행용 최종본**이다. 근거와 출처는 그 문서에 있다.

## 0. 목적과 범위

- **목적**: 실제 대화 코퍼스(TAXI·Verbmobil, 신청 중)를 기다리는 동안, 논문에 쓸 수 있는 CST-S2TT **평가 전용** 합성음 벤치마크를 만든다.
- **질문**: 서로 다른 언어를 쓰는 두 사람이 같은 문맥으로 대화하고 말이 겹칠 때, 시스템이 다음을 해내는가?
  - 번역 품질 유지
  - 적절한 시점·방향으로 번역
  - 겹친 두 발화를 모두 번역
  - 맞장구·끼어들기에 맞게 대응

### 확정된 요구 조건과 반영 위치

| # | 조건 | 반영 |
|---|---|---|
| 1 | 논문용, 리뷰어 설득 | §10 검증 장치 |
| 2 | 기준선과 공통 언어, 영어·독일어 필수, 한국어 포함 | §2 EN↔DE·EN↔KO |
| 3 | 검증된 TTS | §6 Azure(상용) + CosyVoice 3·Qwen3-TTS(공개) |
| 4 | 서로 다른 언어의 동시 발화, 겹침을 일정 비율 이상 | §5 겹침 층 L2 ≥ 25 % |
| 5 | 같은 문맥의 대화, 공평한 스크립트 | §3 병렬 대화에서 화자별 언어 판 선택 |
| 6 | 끼어든 쪽은 들은 만큼만 안다 | §4 정보 인과 규칙 + 누설 검사 |
| – | 원어민 번역 검수 없음 | §7 사람 번역 원천 + LLM 합의 |
| – | 상용 TTS 허용 | §6 |
| – | 평가셋만 | §12 |

## 1. 한눈에

| 항목 | 결정 |
|---|---|
| 언어쌍 | **EN↔DE**(주 비교쌍), **EN↔KO**(어순이 먼 쌍). 화자 언어 배정은 양방향 |
| 내용 | XDailyDialog(일상, EN·DE 전문 번역)와 BConTrasT(과제형, EN·DE 전문 번역). 한국어판은 LLM 합의 번역 |
| 참조 | EN↔DE 는 gold(사람 번역). KO 와 새로 생성한 사건 발화는 silver(합의 번역, 표시해서 따로 집계) |
| TTS | **Azure Neural TTS 판**(상용, 주 결과) + **공개 판**(CosyVoice 3 또는 Qwen3-TTS, 파일럿으로 결정) |
| 입력 조건 | 단일 채널 혼합(주) + 화자별 2 채널(보조). 잡음·잔향·전화 대역 변형 |
| 상호작용 | Normal · Early Turn · Backchannel · Interruption(A 멈춤 / **A 계속 = 동시 발화**) · Explicit Barge-in |
| 겹침 층 | L0 0 % · L1 약 5 % · **L2 ≥ 25 %** |
| 규모 | 언어쌍마다 약 10–12 h, 칸(사건 유형 × 난이도 × 언어쌍)마다 사건 ≥ 300, 보정 분할 약 5 % |
| 공개 | 부분집합 두 개: XDailyDialog 계열 CC BY-NC-SA 4.0, BConTrasT 계열 CC BY-SA 4.0 |
| 예산 | Azure TTS 약 $25–35(최대 $100 이하) + mxc GPU |

## 2. 언어쌍과 비교 대상

| 기준선 | EN→DE | DE→EN | EN↔KO |
|---|---|---|---|
| SeamlessStreaming | ○ | ○ | ○ |
| StreamSpeech | – | ○ | – |
| Hikari | ○ | – | – |
| IWSLT Simultaneous 계열 | ○ | – | – |
| cascade 기준선 B1–B4(ASR + LLM MT + VAD/VAP/Oracle) | ○ | ○ | ○ |

- EN↔DE 는 공개 동시통역 시스템과 직접 비교할 수 있는 공통 쌍이다. TAXI 와도 같은 쌍이라 §10 의 합성→실제 검증에 쓴다.
- EN↔KO 는 우리 초점이다.

## 3. 대화 원천과 “같은 문맥” 구성

1. **원천 선별**:
   - XDailyDialog: 13K 대화, 대화당 평균 7.9 발화, 전문 번역가 50 여 명 + 데이터 전문가 3 명이 20 % 표본 검수
   - BConTrasT: Taskmaster-1 기반 6 영역, Unbabel 전문 번역
   - 선별 기준: 턴 6–16, 발화 길이 분포, 영역 균형, 숫자·고유명사를 포함한 대화의 비율
2. **한국어판**: 영어 원문을 §7 의 합의 절차로 번역한다(silver).
3. **두 화자 구성**: A 턴은 언어 X 판, B 턴은 언어 Y 판에서 가져온다. 두 화자가 같은 문맥을 공유하고 **상대 언어 판이 참조**가 된다.
4. **공평성**:
   - 같은 대화를 네 배정(A=EN/B=DE, A=DE/B=EN, A=EN/B=KO, A=KO/B=EN)에 모두 쓴다. 언어쌍 차이는 언어 때문에만 생긴다
   - 평가 대상 시스템 계열의 LLM 은 사건 발화 생성에 쓰지 않는다
   - 생성 프롬프트·모델·시드를 공개한다
5. **오염 점검**: 대화 앞부분을 주고 다음 턴을 이어 쓰게 해 원문과의 일치율을 잰다. 새로 생성한 사건 발화만 집계한 점수를 함께 보고한다.

## 4. 정보 인과적 상호작용 생성 (조건 6)

**규칙**:
- 상대에게 반응하는 발화는 **그 발화 시작 시점까지 상대가 실제로 말한 내용과 이전 이력에만** 의존할 수 있다.
- 겹친 채 계속 말하는 화자는 상대의 끼어든 내용을 아직 처리하지 않은 것으로 보고, 원래 계획한 말을 이어 간다.

| 사건 | 생성 | 인과 보장 |
|---|---|---|
| Normal | 원 대화 순서, 자연 간격 | 원 내용 그대로 |
| Early Turn | B 의 원래 응답을 A 의 끝 직전에 시작 | **의존점**(B 응답이 쓰는 A 정보가 마지막으로 나온 단어)을 정렬로 찾는다. 시작은 의존점 + 반응 여유 200 ms 이후로만 한다 |
| Backchannel | 듣는 쪽 언어의 맞장구를 A 발화 중 의미 단위 경계에 삽입 | 내용이 없다. 기대 행동은 “번역·전환 없음” |
| Interruption-Stop | A 를 의미 단위 경계 c 에서 반응 지연 200–600 ms 뒤에 자른다. B 의 끼어들기는 A[:c] + 이력만 입력해 생성 | 생성 입력에 A[c:] 를 넣지 않는다 + 누설 검사 |
| **Interruption-Continue**(동시 발화) | B 는 위와 같이 생성하고, A 는 계획한 다음 문장을 이어 말해 B 와 겹친다 | A 의 계속분은 원 스크립트라 B 에 의존하지 않는다. 두 발화 모두 번역 대상이다 |
| Explicit Barge-in | “잠시만요 / Wait / Moment mal” + A[:c] 에 대한 질문 | 위와 같은 인과 생성 + 누설 검사 |

- **난이도**:
  - Easy: 턴 끝 직전
  - Medium: 의미 단위 경계
  - Hard: 핵심 의미가 완성되기 전
  - 의미 단위(MU)는 번역 접두 일관성 기준이다([[output-simulst-translation-unit-survey-20261002]]).
- **자르는 지점 c 는 MU 경계로만** 고른다. A 가 실제로 말한 부분의 참조가 전체 참조의 접두로 성립해야 하기 때문이다.
- **에피소드 = 이력 2–4 턴 + 사건 + 해소 1–2 턴.** 해소 턴도 인과 생성한다. 원 순서를 그대로 둔 긴 세션(Normal·Early Turn·Backchannel)도 따로 둔다.
- **누설 검사**:
  1. 규칙: B 발화의 숫자·고유명사·핵심 명사가 A[c:] 에만 있으면 탈락
  2. 판정 LLM 두 개(EXAONE-4.0, Qwen3.8-27B)가 각각 “A[:c] 와 이력만으로 이 말이 가능한가”를 판정한다. 둘 다 통과한 것만 남긴다
  3. 판정자 간 일치도와 탈락률을 보고한다

## 5. 겹침 설계 (조건 4)

| 층 | 대화 시간 대비 겹침 | 주 사건 | 용도 |
|---|---|---|---|
| L0 | 0 % | Normal | 기존 SimulST 와 같은 조건 |
| L1 | 약 5 % | Early Turn·Backchannel(자연 분포: 겹침 중앙값 약 0.5 s) | 현실 수준 |
| **L2** | **≥ 25 %** | Interruption-Continue·긴 겹침 | novelty 평가의 중심 |

- **정의**:
  - 겹침 비율 = 두 화자의 단어 구간이 동시에 있는 시간 / 대화 전체 발화 시간(강제 정렬 기준)
  - 겹침 단어 비율 = 상대가 말하는 동안 발화된 원천 단어 비율
- **신호 조건**:
  - 화자 레벨 차 −5 … +5 dB
  - 실내 잔향
  - 잡음 SNR 5–30 dB
  - 전화 대역(8 kHz 코덱)
  - 조건마다 분리해서 보고한다
- **시스템 출력 형식**:
  - (시각, 방향 A→B/B→A, 텍스트, 확정 여부) 열
  - 단일 방향 기준선은 방향마다 하나씩 붙인다(2 채널 조건)

## 6. TTS (조건 3)

| 판 | 엔진 | 근거 | 화자 |
|---|---|---|---|
| **상용 판(주 결과)** | Azure Neural TTS(표준 Neural, 필요하면 HD) | 공식 답변상 유료 리소스 출력의 사용·배포 허용. en-US·de-DE·ko-KR 원어민 음성. **WordBoundary 로 단어 시각** 제공 | 언어별 프리셋 원어민 8–12 명, 성별 균형 |
| **공개 판(재현용)** | CosyVoice 3(9 개 언어, 가중치 Apache-2.0) 또는 Qwen3-TTS(10 개 언어, Apache-2.0, 공식 보고 DE WER 1.1–1.2 · KO 1.7 · 화자 유사도 0.78–0.80) | 누구나 재생성 가능 | CC0 참조 음성 복제 또는 음성 설계. 실존 인물 무단 복제 금지 |

- 두 판 모두 평가셋 전체를 합성한다. 주 결과는 상용 판으로 보고하고, 공개 판에서 **시스템 순위 상관**을 보인다.
- 교차 언어 복제(외국어 억양)는 쓰지 않는다. 화자 음색은 대화 안에서 일관되게 둔다.

**품질 보증**(발화 단위로 통과하지 못하면 재합성하고, 논문에 수치로 보고):

| 검사 | 방법 | 기준 |
|---|---|---|
| 명료도 | Whisper-large-v3·Qwen3-ASR 두 개로 재인식 | EN·DE WER ≤ 5 %, KO CER ≤ 5 % |
| 화자 일관성 | 화자 임베딩 코사인 | 화자 안 ≥ 문턱, 화자 간 분리 |
| 자연성 | UTMOS(EN)·DNSMOS·TTSDS | 두 판과 실제 대화 녹음 표본을 같은 지표로 비교 |
| 단어 시각 | Azure WordBoundary vs 강제 정렬(MFA 또는 Qwen3-ForcedAligner) | 차이 분포 보고 |

## 7. 참조 번역

- **gold**: XDailyDialog·BConTrasT 의 EN↔DE 사람 번역.
- **silver**: 한국어 전체 + 새로 생성한 사건·해소 발화. 절차:
  1. **세 번역기 독립 번역**: Qwen3.8-27B(Apache-2.0) · MADLAD-400-10B-MT(Apache-2.0) · EXAONE-4.0(내부 판정용)
  2. **일치 검사**:
     - MetricX-24 하이브리드 QE(Apache-2.0, 주)
     - CometKiwi(보조)
     - 역번역 의미 유사도(LaBSE)
     - 숫자·고유명사 일치
  3. 셋 중 둘 이상 일치하면 통과한다. **공개 참조는 Apache 계열 번역(Qwen3.8 또는 MADLAD) 중에서** 판정 LLM 이 고른다. EXAONE 출력은 라이선스상 공개하지 않는다
  4. 불일치 발화는 평가셋에서 빼고 탈락률을 보고한다
- **부분 참조**: Interruption-Stop 의 A 는 MU 경계 c 에서 자른다. 참조는 c 까지 정렬된 접두다.
- **채점**:
  - 다중 참조 BLEU·chrF
  - 참조별 COMET 평균
  - 참조 없는 QE
  - gold / silver 구간 분리 집계
  - EN↔DE 는 gold 와 silver 를 모두 만들어 **두 점수의 시스템 순위 상관**을 보고한다

## 10. 리뷰어 설득 장치

1. **합성→실제 일반화**: TAXI(DE↔EN) 확보 후 L0/L1 조건에서 시스템 순위의 실제-합성 상관.
2. **TTS 두 판의 순위 상관**: 상용 판 대 공개 판.
3. **참조 신뢰성**:
   - gold 대 silver 의 순위 상관(EN↔DE)
   - 합의 탈락률
   - 판정자 일치도
4. **통계 검정력**: 칸마다 사건 ≥ 300, 짝 bootstrap 신뢰구간.
5. **전면 공개**: 스크립트·프롬프트·시드·혼합 코드·품질 수치.
6. **한계 명시**:
   - 합성 운율과 계획된 대화
   - KO 참조가 silver 라는 점
   - 고겹침 층은 의도적 스트레스 조건이라는 점

## 11. 라이선스·윤리

- **공개 단위**: 두 ShareAlike 라이선스(BY-SA, BY-NC-SA)가 서로 호환되지 않는다. 그래서 부분집합 두 개를 **각자의 라이선스로** 낸다.
- **Azure**:
  - 유료(종량제) 리소스로만 생성한다
  - 입력 텍스트 권리는 위 라이선스로 확보돼 있다
  - 합성음임을 데이터 카드에 표시한다
- **EXAONE-4.0**: 출력이 비상업이고 경쟁 모델 개발에 쓸 수 없다. 내부 판정에만 쓰고 공개물에는 넣지 않는다.
- **DeepL**: 약관이 MT 개발·벤치마크 사용을 금지하므로 쓰지 않는다.
- **잡음**: 혼합본은 재배포 가능한 잡음(RIRS_NOISES 등)만 쓴다. 나머지 조건은 재현 스크립트로 공개한다.
- **음성**: 실존 인물 음색을 무단 복제하지 않는다. 비밀 키는 `.env.local` 에만 둔다.

## 12. 규모·예산·일정

| 단계 | 기간 | 내용 | 관문(통과 기준) |
|---|---|---|---|
| **S0** 파일럿 | 1 주 | 원천·모델 확보(T5 다운로드 → 사용자 업로드). Azure·CosyVoice 3·Qwen3-TTS 언어별 50 문장 합성, 품질 지표 | 언어마다 한 엔진 이상이 WER/CER ≤ 5 %. 공개 판 엔진 결정 |
| **S1** 스크립트 | 1–2 주 | 대화 선별, KO silver 번역(합의), 오염 점검 | KO 합의 통과율 ≥ 85 % |
| **S2** 사건 | 2 주 | MU 경계·의존점 계산, 인과 사건 생성, 누설 검사, 사건 발화 번역 | 누설 검사 이중 통과, 칸마다 사건 ≥ 300 확보 |
| **S3** 합성·혼합 | 1–2 주 | 두 판 합성, 품질 보증 재합성, 겹침 층·신호 조건 혼합, 라벨·참조 패키징 | 품질 기준 통과, 층별 겹침 비율 목표 달성 |
| **S4** 기준선 | 1–2 주 | B0–B4 실행(2 채널·혼합), 지표 sanity, kill criterion | [[task-cst-kill-criterion-check]] 판정 |

- **규모**: 언어쌍마다 약 10–12 h(에피소드 약 1,000 + 긴 세션), 보정 분할 약 5 %.
- **예산**:
  - Azure 표준 Neural 약 $16 / 100 만 자 × 약 100–150 만 자 = **$16–24**(HD $22–33)
  - 판을 추가하거나 재합성해도 $100 이하
  - 나머지는 mxc GPU(합성·번역·판정)
- **실행 위치**:
  - 공개 TTS·번역·판정: mxc 호스트 GPU
  - Azure 호출: 로컬(키는 `.env.local`). mxc 망에서 Azure 엔드포인트가 열리는지는 S0 에서 확인한다

## 15. 자체 검토와 보완 (v1.1, 2026-10-03)

v1.0 을 리뷰어 입장에서 다시 보고 찾은 약점과 보완:

| # | 약점 | 영향 | 보완 |
|---|---|---|---|
| 1 | **원천 턴이 짧다**(XDailyDialog 평균 11.5 토큰/발화). A 가 두 문장 이상 말하는 턴이 적어 Interruption-Continue·L2(≥ 25 %) 목표를 못 채울 수 있다 | novelty 칸의 사건 수 부족 | S0 에서 다문장 턴 통계를 먼저 잰다. 부족하면 같은 화자의 연속 발화를 한 턴으로 합치거나 다문장 턴 비율이 높은 대화를 우선 선별한다. 겹침 목표는 실측 후 확정한다 |
| 2 | **핵심 사건의 참조가 silver 다**. 끼어들기·해소 발화는 새로 생성하므로 EN↔DE 에서도 사람 번역이 없다 | novelty 결과의 신뢰성 공격 | 사건 발화는 짧다(대답·질문). 다중 참조와 QE 를 병기한다. 사건 칸 점수는 상호작용 지표(시점·방향·놓침)를 주로 하고, 번역 품질은 보조로 둔다. 한국어 쪽은 팀(한국어 원어민)이 표본을 직접 확인한다 |
| 3 | **Hard 난이도와 부분 참조가 모순된다**. Hard 는 “핵심 의미 완성 전”에서 자르는데, 그런 자리는 정의상 MU 경계가 아니라 부분 참조를 전체 참조에서 잘라낼 수 없다 | Hard 칸 번역 채점 불가 | 자르는 위치를 둘로 나눈다. Easy·Medium 은 MU 경계에서 자르고 부분 참조로 채점한다. Hard 는 비경계에서 자르고 **번역 품질은 채점하지 않는다**. 대신 기대 행동(조각을 지어내 완성하지 않기, Stop Latency, 이후 방향 전환)만 본다 |
| 4 | **동시 발화가 비현실적이라는 지적**. 실제 대화의 지속 겹침은 짧다(중앙값 약 0.5 s) | L2 결과의 대표성 | L2 는 스트레스 조건으로 명시하고, 주 결과는 L1 로 함께 보고한다. TAXI 로 실제 겹침 분포를 확인한다. 상대 언어를 못 알아듣는 통역 대화에서 겹침이 더 잦은지는 가설로만 적고 근거 없이 주장하지 않는다 |
| 5 | **분리 기준선이 빠졌다**. 단일 채널 혼합에서 가장 먼저 떠올릴 대안은 “음성 분리 + 2×SimulST” 다 | 혼합 조건 우위가 기준선이 약해서라는 지적 | **B2-Sep**(음성 분리 모델 + 화자 할당 + 2×SimulST)를 추가한다 |
| 6 | **방향 판단이 언어 인식으로 쉽게 풀릴 수 있다**. 두 화자 언어가 다르므로 LID 만으로 방향을 정할 수 있다 | “방향 판단” 기여 축소 | **B2-LID**(프레임 LID 라우팅 + 2×SimulST)를 추가한다. 우리 기여를 방향 판단 자체가 아니라 겹침·맞장구·끼어들기에서의 쓰기/멈춤/전환 시점으로 위치 짓는다 |
| 7 | **TTS 운율의 비대화성**. 겹침에 대한 반응(롬바드 효과·말 끊김)이 없다 | 음향 현실성 | 두 판 순위 상관과 sim2real 로 대응한다. 한계에 명시한다 |
| 8 | **겹친 출력의 채점 규약이 덜 정의됐다** | 재현성 | 방향별 출력 스트림을 해당 화자의 참조 턴에 시간 정렬로 붙이는 규약(정렬 창, 미배정 출력 = 잘못된 방향)을 S4 전에 지표 도구에 고정한다([[task-cst-bench-v0-metrics]]) |

기준선 표는 다음으로 갱신한다:
- B0 오프라인 ST
- B1 2×SimulST
- B2 VAD 라우팅
- **B2-LID**
- **B2-Sep**
- B3 VAP 라우팅
- B4 Oracle 턴 경계
- B5 제안 joint 모델
