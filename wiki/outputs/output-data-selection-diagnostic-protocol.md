# 세 가지 우선 진단의 실행 방법

**실행 결과:** [[output-data-selection-diagnostic-v04]]. 방송 원주석/사본 대조·AMI 문맥 사본·VoxPopuli
6개 진단과 사람 검수 보류 적용을 완료했다. 아래는 실행 전 계획이며 전사 확정과 학습 승인은 별도다.

## 결론과 범위

전체 ASR 재추론보다 **실패 원인을 확인할 작은 증거 묶음**이 먼저다.
실행 순서는 방송 생성 경로 → AMI 원음 문맥·음량 → VoxPopuli 오류 분리를 권한다.
이는 새로운 계획이며, 이 문서 작성 중 원음·타깃 수정이나 서버 작업 제출은 하지 않았다.
기존 32개를 전부 다시 검수하지 않는다.

## 0. 공통 선행 작업: 사람 검수 예외표

기존 32개 key와 입력 지문을 기준으로 원형 검수 라벨·메모를 연결한다. 실패 11개와
pass/메모 쟁점을 추적하되, 사람 fail은 교사 합의로 자동 해제할 수 없게 한다.

새 진단 기록의 최소 필드:

- `source`, `key`, 원음/주석/TN/manifest hash, 원래 `human_labels`, `human_note`.
- `cause`: `label_content`, `crop_boundary`, `channel_mapping`, `low_audibility`,
  `representation_only`, `pipeline_mismatch`, `unresolved` 중 증거가 지지하는 항목(복수 허용).
- 비교한 필드·파형·원음 시간 범위와 `proposed_text`, 제안 이유, 검수자가 확정한 전사.
- 전사·시각·화자·턴 각각의 상태와 후속 판정자/시각. 초기 `training_eligible=false`.

원형 fail을 수정하지 않고 별도 후속 판정으로 해결 이력을 남긴다. 검수 미해결 구간을
대화에서 삭제해 시간을 압축하거나 무음/빈 전사 정답으로 바꾸지 않는다.

## 1. 방송: 원 JSON부터 타깃까지 한 행 재현

대상: `vr_m_001_370_049_0348`.

**코드에서 확인된 사실:** [빌더](../../experiments/s1_build_manifest.py)의 `aihubbc_utts`는
`발음전사 → target_ko(..., "aihubbc") → text`를 사용하고,
`철자전사 → raw → raw_text`를 별도로 보존한다.
[리더](../../vapasr/data/aihub.py)의 `iter_bc`에는 `전사작업본`도 있다.
따라서 `raw_text=네.` / `text=네 네 네`만으로 정규화 버그를 확정할 수 없다.
해당 원 JSON의 실제 필드값은 아직 이번 진단으로 재확인하지 않았다.

실행:

1. 원 오디오 ZIP/member와 전사 ZIP/member를 확정하고 JSON의 **발음전사·철자전사·전사작업본**을 보존한다.
   같은 stem이 언어쌍별로 중복될 때 리더는 첫 항목을 선택하므로,
   후보가 여러 개면 라벨 내용·오디오 hash를 비교해 서로 다른 사본을 결합했는지 확인한다.
2. manifest 생성 당시 TN/코드 지문을 확인하고, 같은 버전으로 발음전사 한 행을 다시 변환한다.
   현재 코드와 버전이 다르면 두 결과를 구분해 기록한다.
3. `발음전사 → TN 결과 → 저장 manifest → 선별 후보`를 나란히 비교한다.
4. 원래 파형을 유지한 채 실제 반복 수를 확인한다. 사용자의 기존 `네 네` 판단은 근거로 사용하되,
   `네`도 허용한다는 의미상 판단과 streaming 학습용 정확한 반복 수를 분리한다.

판정:

| 관측 | 결론/다음 행동 |
|---|---|
| 원 발음전사부터 `네 네 네`, TN도 동일 | 파이프라인 반복 생성 오류가 아니라 원 라벨과 음성의 일치 문제를 검수 |
| 원 발음전사는 1~2회, TN 단계에서 3회 | TN/파서 재현 오류를 좁히고 회귀 테스트를 만든 뒤 별도 수정 |
| TN 재현은 맞지만 manifest만 다름 | 오래된 버전·잘못된 source join·이후 변환 이력 조사 |
| 동일 stem의 사본이 서로 다름 | 파일명만으로 dedup/join하지 않고 해당 충돌 집합을 보류 |

완료 조건: 최초 차이가 생긴 단계 또는 의도된 필드 차이를 설명하고,
확정된 target이 동일 입력·동일 코드에서 재현되어야 한다.
원인이 공통 코드이면 해당 조건을 만족하는 DB 행에 영향 범위를 확장한다.
고립된 원주석 오류면 국소 교정 후보로 남긴다. `raw_text != text`를 전체 오류 규칙으로 쓰지 않는다.

## 2. AMI: 조용한 발화인가, 다른 위치/화자인가

대상: `ES2010d / A_00018`, `Headset-0`, 시작 234.102초, 길이 약 0.732초.
타깃·세 교사는 `Right`, 사람 검수는 들리지 않음이다.

실행:

1. [AMI 리더](../../vapasr/data/dialogue_corpora.py)의 `AmiAnnotations`가 읽는
   `meetings.xml`의 agent→Headset 매핑과 원 segment/word XML을 대조한다.
   stereo 파일 안 두 채널의 동일성과, **서로 다른 Headset 파일의 화자 매핑**은 별개다.
2. 원 파일에서 재추출한 crop hash가 기존 QC·청취 사본과 같은지 확인한다.
   브라우저 재생 문제와 데이터 자체 문제를 먼저 분리한다.
3. 같은 시간축으로 (a) 원 crop, (b) 앞뒤 각 2초 문맥,
   (c) 원 crop의 진단용 증폭 사본을 만든다. 필요할 때 다른 Headset도 같은 시각으로 비교한다.
4. 증폭은 고정 gain 후보 +12 dB에서 시작하되 peak가 −1 dBFS를 넘지 않게 제한하고 실제 gain을 기록한다.
   정상화·denoise·시간 이동 없이 별도 사본만 제공한다. 증폭은 잡음도 키우므로 음성 존재의 증명이 아니다.
5. 사람이 먼저 후보 텍스트를 숨긴 상태에서 들린 내용을 적고, 이후 원전사·교사와 비교한다.
   여전히 모호하면 추가 문맥/진단용 파형에 한해 교사 재추론을 보조로 사용한다.

판정:

- 같은 위치·대상 화자의 `Right`가 확인됨: 낮은 가청성 문제로 기록하고 전사 보류 해제 후보.
- 발화가 crop 밖 또는 다른 Headset에서 확인됨: 경계/매핑 오류 조사. 원음과 매핑 근거 없이
  가장 크게 들리는 채널을 화자의 정답으로 선택하지 않는다(누설음 가능).
- 끝내 확인 불가: `unresolved` 유지. 무음 정답이나 교사 환각으로 단정하지 않는다.

완료 조건: 사람의 재청취와 원주석·채널·시간축 근거가 일치하거나,
해결 불가 사유가 명시되어 해당 감독만 보류되어야 한다. ASR 전사 해결만으로 EOT를 승인하지 않는다.

## 3. VoxPopuli: 전사 실패 6개의 원인을 나누기

| 사례 | 우선 비교 | 잘못된 자동 조치 |
|---|---|---|
| `getting so much` / `so much` | 원 세션에서 `getting`이 VAD 밖인지, 원 라벨에만 있는지 | 길이 차이만 보고 임의 padding |
| `i understand…` / `and i understand…` | crop에 실제 추가 단어가 들어오는지 | 일괄 시작점 이동 |
| `let us` / `let's` | 실제 축약 발음과 lexical 규약 | 메모만으로 화자·경계까지 수정 |
| `who attend` / `attending` | 실제 발화 어순과 원전사의 문어체 수정 여부 | 문법적으로 자연스러운 쪽을 자동 채택 |
| ECR 문장 | 현행 `score_en`에서 세 교사와 타깃이 이미 동일함을 표시 | 표시 방식 선호를 단어 오류로 계산 |
| 긴 fisheries 문장 | `in/on`, 반복, 말미 `Thank you` 등 불일치 위치별 청취 | 교사 중 하나의 전체 문장 무검수 채택 |

전체 ID와 원형 검수는 [[source-data-selection-human-review-v03]] 및 연결된 raw JSON을 따른다.

실행:

1. 원 annotation의 `original_text`, `normed_text`, `start/end`, `vad`와 배포 crop을 연결한다.
   [기존 VAD 대응표 생성기](../../experiments/selection_vad_audit.py)의 구간별 source↔clip sample 대응을 재사용한다.
2. 원 세션 음성이 로컬에 있는지 **먼저 확인**한다. 있으면 문제 단어 주변 문맥을 추출하고,
   여러 VAD 구간이 연결된 경우 각 접합부를 표시한다. 실제 파형 대응도 검증한다.
3. 원 세션이 없으면 인접 배포 clip은 보조 증거로만 쓴다. 이들을 이어 붙여 원래 무음·시간축을
   복원했다고 간주하지 않는다. 별도 원음 확보가 필요하면 용량·접근 조건을 확인하고 요청한다.
4. 정정이 필요한 단어 위치와 확정 문자열을 기록한다. 같은 음성의 표기 차이와 실제 누락/추가를
   분리하고, 표시 선호만 있는 항목은 lexical 타깃 변경을 제안하지 않는다.

완료 조건: 각 사례에 `정확한 전사 교정`, `crop/시간축 복구`, `표현 차이`, `미해결` 중
근거 있는 후속 판정이 있어야 한다. 원래 human fail은 보존한다.
원 세션이 없어도 현재 crop의 전사를 확정할 수는 있으나, 그 경우 원대화 타이밍 자격은 별도 보류한다.
배포 규약과 파일 길이의 일치는 이미 확인됐으므로 같은 전량 길이 검사를 반복하지 않는다.

## 4. 결과물과 전량 선별 진입 조건

첫 실행의 결과물은 **검수 예외표 + 방송 필드 추적표 + 문제 구간 청취 페이지 + 원인별 판정표**다.
필요한 재청취만 요청하고, 표본 수를 늘리는 것 자체를 완료 조건으로 삼지 않는다.

- 최초 파일/필드/파형 진단은 CPU로 수행한다. 소규모 작업에 무조건 32 worker를 쓰지 않으며,
  DB 영향 범위 검사처럼 I/O 병렬화가 유효할 때만 최대 32까지 사용한다.
- 기존 교사 출력은 입력 파형·모델·TN 지문이 같을 때 재사용한다. 변경된 crop·gain·문맥은
  별도 지문과 결과 경로를 쓴다. 재추론이 필요해도 처음에는 GPU 1장으로 충분한지 확인한다.
  사용자 상한인 동시 최대 4장을 넘기지 않는다.
- 진단 뒤 수정하려면 해당 범위만 새 manifest/override로 만들고 회귀 테스트·재검수를 거친다.
  텍스트/파형/시간축 변경에 따라 정렬·특징·교사·시퀀스 중 영향을 받는 캐시를 무효화한다.
- 해결되지 않은 행은 보류하고, 기준이 확정된 DB/하위집합의 screening은 별도로 진행할 수 있다.
  이 3개 진단의 해결은 전체 DB 품질 인증이나 미검수 DB calibration의 대체가 아니다.

현행 lexical TN 변경, 실제 반복 생략, 숫자 display 타깃 전환은 이 진단과 분리해 결정한다.
