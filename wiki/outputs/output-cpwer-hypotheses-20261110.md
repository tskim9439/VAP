# cpWER 격차를 줄일 가설과 검증 계획 (2026-11-10)

사용자 요청(2026-11-10)
- "기존의 맥락을 제외하고 한번 cpWER 성능을 높힐 수 있는 방안은 새로운 시각으로 고안해봐. 이론적인 가설을 세우고."
- "그럼 우리 모델에서 N3D 모듈만 Freeze 시키고 Encoder 와 LLM 은 모두 풀고 학습시키는 방향이 낫지 않을까?" → 3 절 대조 실험 E18
- "그럼 다시 너의 가설과 제안을 정리해줘."

이 문서는 가설과 계획이다. 1 절과 가설 4 의 진단 결과만 잰 값이고, 나머지는 아직 검증하지 않았다.

**2026-11-10 갱신**: 가설 2 는 사용자가 기각했다("인코더를 1.12s 청크로 되돌리는 것은 기각"). 가설 4 는 진단에서 기각됐다(아래). 가설 1 도 사용자가 기각했다("화자 마다 Encoder 를 돌리는 건 연구 목표 측면에서 어긋나는 거 같아서 기각"). 연구 목표는 인코더 한 번 통과 + LLM 한 스트림이다(고정 N3D 활동 입력은 허용). 남은 것은 가설 3 의 측정과 E18 이다.

## 1. 출발점 (잰 것)

  - 인코더 위층을 LLM 손실로 함께 학습해도(E15a 절제) 그대로다(42.9 → 44.3 %). 슬롯 조건을 위층에 넣은 E15b 는 슬롯 경로가 쓰이지 않았다.
  - 인코더 단독 검증 P1(우리 인코더 + 0 층 화자 커널 + RNN-T, 6,000 step)은 누구 말인지는 갈랐지만 겹친 말은 지웠다(둘 겹침 삭제 32.0 % 대 Parakeet 11.4 %) — [[output-ssa-papers-review-20261106]] 7 절.
  - 단일 화자(ESB AMI) WER: 원 모델 0.32 s 청크 16.69 %, 1.12 s 청크 15.04 %, E13 δ10 16.47 % — 같은 문서 6 절.

## 2. 가설

### 가설 1 — 분리를 토큰 손실로 가르치는 것이 병목이다 (겹친 말)

- **결정(2026-11-10 사용자): 기각.** 제안한 구조는 겹친 구간에서 인코더를 화자 수만큼 돌린다(LLM 은 한 스트림). 이것이 연구 목표(인코더 한 번 + LLM 한 스트림)에 어긋난다. 같은 이유로 Parakeet·SSA 식 화자 커널과 E15b 식 슬롯별 인코더 위층도 하지 않는다. 아래는 기록으로 남긴다.
- "토큰 손실은 성긴 신호다"라는 이론 자체는 기각되지 않았다. 인코더를 한 번만 돌리면서 이 신호를 쓰는 길(학습 때만 쓰는 보조 머리)은 6 절에 후보로 적는다.

- 이론
  - 받아쓰기 정답은 화자당 초당 토큰 3–4 개다. 분리는 프레임마다 "이 소리 중 어느 것이 그 화자 것인가"를 정하는 함수다. 성긴 신호로는 "확실할 때만 쓰고 나머지는 지운다"까지만 배운다.
  - P1(누구인지는 가르고 겹친 말은 지움), SSA 의 200k step 대 우리 6k step, E15b 의 쓰이지 않은 슬롯 경로(정보 없는 경로는 LLM 이 무시하고, 무시된 경로는 신호를 못 받는다)가 이 설명과 맞는다.
- 제안: 글자 대신 특징 자체를 정답으로 준다(특징 증류). 우리 모델에 두 단계로 적용한다.
  1. 인코더 증류(디코더 없음): 교사는 고정한 원래 인코더에 그 화자 혼자만의 소리를 넣어 나온 특징이다. 학생(P1 구조 — 0 층 화자 커널)은 섞인 소리와 그 화자 활동을 받아 이 특징을 프레임마다 맞춘다. 신호가 초당 12.5 프레임 × 1,024 차원이 된다. 전사가 필요 없어 단일 발화를 매번 새로 섞어 쓴다. 혼자 말 구간은 목표가 원래 특징 그대로다.
  2. Qwen 에 붙이기: 한 스트림 안에서 각 화자 블록이 자기 화자 특징을 읽게 하고(E15b 의 슬롯 특징 경로), LLM 을 짧게 다시 맞춘다. LLM 디코드는 그대로 한 번이다.
- 판단: 본 모델의 AMI 회의 통째 cpWER 과 둘 겹침 놓침(2 단계). 1 단계에서는 특징이 교사와 얼마나 가까운지와, 선택으로 P1 과 같은 RNN-T 조각 평가(둘 겹침 놓침 42.7 % → 33 % 아래)를 본다. RNN-T 는 재는 자일 뿐이다.
- 겹침에서 두 화자를 모두 받아쓰는 능력이 약해지지 않게 하는 조건(2026-11-10 사용자 질문 "화자 혼자일때의 특징을 읽도록 증류하면 … 약화되는 것이 아닌가?")
  - 인코더를 말하는 화자마다 한 번씩 돌린다. 겹침에서는 A 조건으로 한 번, B 조건으로 한 번 돌아 두 화자의 특징이 모두 나온다.
  - 지금의 섞인 소리 특징 경로는 그대로 둔다. 원래 인코더는 고정한 채 따로 두고, 증류한 인코더는 화자별 특징 전용이다. 화자별 특징은 더해지는 정보다.
  - 하지 않는 것: 증류한 인코더로 섞인 경로까지 바꿔 끼우는 것(한 화자만 남기도록 배운 가중치라 다른 화자가 더 지워질 수 있다), 섞인 특징을 빼고 화자별 특징만 주는 것(증류가 못 꺼낸 구간에서 지금보다 나빠질 수 있다).
- 위험
  - 2 단계는 E15b 가 실패한 자리다. 이번에는 붙이는 시점에 경로가 이미 화자별 정보를 담고 E13 이 읽던 특징 공간과 같다는 점이 다르지만, LLM 이 실제로 쓰는지는 재 봐야 안다.
  - 화자 혼자만의 깨끗한 소리는 합성 대화에서만 바로 얻는다. 실제 회의는 개별 헤드셋 채널이 있어야 한다(학습 경로 확인 안 함).
  - 겹친 구간에서 인코더를 말하는 화자 수만큼 돌린다.
  - SSA 는 토큰 손실만으로 성공했다. 이 가설은 "불가능"이 아니라 "효율"에 대한 것이다.

### 가설 2 — 지연 예산을 잘못된 곳에 쓰고 있다 (혼자 말)

- 이론: 인코더 특징은 손실 요약이다. 인코더가 0.32 s 만 앞을 보고 버린 정보는 디코더가 0.92 s 를 기다려도 되찾지 못한다.
- 근거: 디코더 지연 0.92 s 로 얻은 것은 0.2 pt(16.69 → 16.47), 인코더 앞보기 1.12 s 로 얻는 것은 1.65 pt(16.69 → 15.04)다.
- 제안: 인코더를 1.12 s 청크로 돌리고 디코더는 청크가 끝나면 바로 쓴다. 최대 지연이 0.92 s → 1.12 s 로 늘지만 Parakeet 과 같은 조건이다.
- 검증: E13 에 1.12 s 청크 특징을 그대로 넣어 단일 화자 WER 이 15 % 쪽으로 내려가는지 본다(평가만, 옵션 구현 필요). 내려가면 그 설정으로 다시 학습한다.
- **결정(2026-11-10 사용자): 기각.** 인코더 청크는 0.32 s 로 둔다. 따라서 혼자 말 격차(1.6 / 2.5 pt, 대부분 대치)를 줄일 수단이 지금은 없다.

### 가설 3 — 한 스트림이 이길 수 있는 곳은 교차 화자 정보다

- 이론: 화자별 구조는 화자마다 따로 추론해 상대가 방금 한 말을 쓰지 못한다. 한 스트림은 두 화자의 말을 함께 추론한다. 같은 음향 증거라면 함께 추론하는 쪽이 원리적으로 지지 않는다. 쓸 곳은 맞장구·질문의 답·따라 말하기처럼 상대 말에서 예측되는 말이다.
- 검증: 겹친 구간 단어의 정답 확률을 상대 슬롯 글자를 보여 줄 때와 가릴 때로 나눠 잰다(정답 강제 평가 1 회).
- 읽기: 차이가 크면 "증거는 화자별로(가설 1), 추론은 한 스트림에서"가 Parakeet 을 넘는 경로다. 거의 없으면 겹친 말에서는 비기는 것이 상한이다.

### 가설 4 — 삭제가 삭제를 부른다 (보조)

- 이론: 학습은 정답 이력만 본다. 한 번 빠뜨리면 "이 화자는 말이 없었다"는 이력 위에서 다음을 쓰게 되어 계속 빠뜨린다.
- 근거: 단일 화자에서 연속 10 단어 이상 삭제가 우리 삭제의 9 %, 원 모델은 1–2 % 다.
- 검증: 기존 출력에서 바로 앞 단어를 놓쳤을 때와 맞혔을 때의 놓침률을 우리와 Parakeet 에서 비교한다(GPU 없음).
- 맞다면: 이력에서 일부 단어를 지우고 이어 쓰게 하는 학습을 넣는다. [[output-overlap-rl-design-20261106]] 은 같은 문제를 강화학습으로 다루는 설계다.
- **진단 결과(2026-11-10) — 기각.** `gap_diag.py --dump`(Whisper 정규화, 출력 재귀속 3,1, 받아쓰기 = orc 상태) → `raw/sources/experiments/2026-11-10-del-runs/del_runs.py`. 맥에서 T5 의 원출력 행으로 돌렸다(AMI eval 16 회의, 참조 단어 87,071 개, 유형 합은 표준과 같다 — 23.51 / 29.78, 15.90 / 20.52).

| IHM-mix / SDM | E13 · N3D + 재귀속 | Parakeet + N3D |
|---|---|---|
| 바로 앞 단어가 삭제일 때 이 단어 삭제율(전체) | 60.7 / 54.2 % | 61.2 / 55.2 % |
| 같은 것, 혼자 말 → 혼자 말 | 60.0 / 46.0 % | 64.8 / 52.9 % |
| 같은 것, 겹침 직후 혼자 말 | 44.6 / 44.8 % | 52.9 / 43.7 % |
| 앞 단어가 맞았을 때 삭제율(삭제가 시작되는 비율), 혼자 말 | 3.1 / 4.0 % | 2.4 / 3.3 % |
| 같은 것, 겹친 단어 | 14.1 / 16.2 % | 6.3 / 9.0 % |
| 삭제 단어 중 10 단어 이상 묶음 몫(묶음 수) | 18.9 % (59) / 4.0 % (31) | 28.7 % (51) / 10.4 % (31) |
| 삭제 단어 중 2–4 단어 묶음 몫 | 38.1 / 47.4 % | 29.8 / 39.6 % |
| 겹침에서 혼자 말로 번진 삭제(혼자 말 삭제 중 몫) | 10.0 / 4.5 % | 15.2 / 3.8 % |
| 삭제율 혼자 말 · 겹친 말 | 6.8 · 22.8 / 6.8 · 23.7 % | 6.1 · 11.6 / 6.5 · 16.4 % |
| 대치율 혼자 말 · 겹친 말 | 6.1 · 22.0 / 9.7 · 27.1 % | 4.7 · 11.5 / 6.7 · 15.3 % |

  - 삭제가 이어지는 정도는 우리가 Parakeet 보다 크지 않다(혼자 말에서는 오히려 작다). 긴 삭제 묶음도 Parakeet 쪽 몫이 더 크고 묶음 수는 비슷하다. 겹침에서 혼자 말로 번지는 삭제도 더 많지 않다.
  - 다른 것은 겹친 구간에서 삭제가 **시작되는** 비율(2 배)과 2–4 단어짜리 짧은 묶음이다. 겹친 동안의 증거 부족(가설 1 쪽)과 맞고, 이력 때문에 이어지는 삭제와는 맞지 않는다.
  - 혼자 말은 삭제가 같고(6.8 대 6.1 / 6.8 대 6.5 %) 대치만 뒤진다. 겹친 말은 삭제·대치가 둘 다 약 2 배다.
  - 셈의 한계: 편집 거리 정렬이 어긋난 구간에서 삭제를 대치 앞에 몰아 둔다(앞 단어가 대치일 때 삭제율 0 %). 그래서 "앞이 삭제일 때"의 값 자체는 부풀려 있고, 같은 정렬을 쓴 두 시스템의 비교만 읽는다.
  - 이력 지우기 학습은 하지 않는다.

## 3. 대조 실험 E18 — 인코더 전체를 풀고 LLM 과 함께 학습 (사용자 제안)

- 내용: N3D 만 고정하고 인코더와 LLM 을 함께 학습한다. E17 과 데이터·step·시작점을 같게 두고 인코더 고정만 푼다(인코더 학습률은 E15a 처럼 1e-5). E17 이 인코더 고정 쪽 대조다.
- 예상(가설 1 의 반대편 예측): LLM 이 받는 것이 여전히 섞인 소리 특징 한 줄이라 겹침 놓침은 거의 그대로이고, 혼자 말이 조금 나빠진다.
  - 근거: 같은 계열 인코더를 한 인스턴스 구조로 전체 학습한 NVIDIA WL-SOT 가 AMI 23.8 / 30.02(정답 활동)로 지금 우리 수준이고, 단일 화자 WER 도 7.16 → 16.95 로 나빠졌다([[output-ssa-papers-review-20261106]] 1 절). E15a 절제도 겹침 놓침이 줄지 않았다.
  - 여지: E15a 는 위 절반만 풀었고 겹침 데이터가 거의 없었다. WL-SOT 는 디코더가 RNN-T 다. "인코더 전체 풀기 + 겹침 75 %"는 우리 모델로 잰 적이 없다.
- 판단: 둘 겹침 놓침이 E17 보다 뚜렷이 내려가는가, 혼자 말 놓침이 나빠지지 않는가.
- 비용: E17 과 같다(2 노드 약 7 시간 + 평가). 24 층을 다 풀 때의 GPU 메모리는 스모크로 먼저 확인한다.
- **준비(2026-11-11, 사용자 "응 E18 준비해줘. low_p_hpc 로 제출할거야")**: `slurm/submit-q17-e18.sh`(run `q17-e18-enc`, 평가 묶음 `q17-e18*`), 스모크 `raw/sources/experiments/2026-11-11-e18/e18_smoke.sh`.

## 6. 인코더 한 번 + LLM 한 스트림 안에 남은 후보 (2026-11-10, 정해지지 않음)

- **E18**(3 절): 인코더를 풀고 LLM 과 함께 학습한다. 추론 구조는 지금과 같다.
- **E18 + 학습 때만 쓰는 보조 신호**: E18 에 더해, 인코더의 특징 한 줄에서 각 화자의 "혼자일 때 특징"을 작은 보조 머리로 되살릴 수 있어야 한다는 손실을 학습 때만 준다. 추론 때는 보조 머리를 떼고 인코더 한 번·특징 한 줄·LLM 한 스트림 그대로다. 가설 1 의 이론(성긴 토큰 손실)을 구조를 바꾸지 않고 쓰는 길이다. 사용자 확인(2026-11-10): "학습할 때 보조 헤드 쓰는 건 괜찮아."
- **가설 3 측정**: 상대 화자 글자가 겹친 단어를 얼마나 돕는지 잰다. 한 스트림의 원리적 이점이 실제로 있는지 알려 준다.
- 혼자 말 대치 격차는 열린 문제다(가설 2 기각).
- 화자 귀속(0.9 / 1.65 pt)에 대한 참고: 우리 귀속 오류의 약 70 % 는 5 단어 이하 묶음(겹침·차례 경계)이다. 글자 문맥으로 짧은 구간만 고치는 방법과 그 한계 → [[source-diarizationlm-2401-03506]]

## 7. 보조 헤드 진단 — 구현 (2026-11-11, 사용자 "보조 헤드 진단부터 구현해줘")

- **묻는 것**: 지금 인코더가 내는 특징 한 줄(섞인 소리 → 고정 인코더 한 번)에 겹친 구간의 각 화자 말이 얼마나 남아 있는가. 남아 있으면 병목은 LLM 이 읽는 쪽이고, 없으면 인코더가 버린 것이다(→ 인코더를 풀고 보조 손실로 학습).
- **구성**(`experiments/ssa_head_probe.py`, `slurm/ssa-head-probe.sbatch`, `slurm/submit-ssa-head.sh`, 시험 `tests/test_ssa_head_probe.py`)
  - 인코더는 우리 모델의 것(E13 final 의 `encoder.enc.*`)을 얹어 고정하고 한 번만 돌린다. E16·E17 도 이 인코더를 고정해 쓴다.
    - 확인(2026-11-11): E13 의 인코더는 원 Nemotron 3.5 와 636 개 텐서가 모두 다르다(최대 차 0.17 — 앞 단계에서 학습됐다). P1·P2 는 원 인코더에서 시작했다.
    - 전처리 → 인코더 출력 Z 는 우리 LLM 어댑터가 받는 특징 그대로다(fp32, 언어 프롬프트 융합 전).
  - 헤드(37.8M): Z 에 대상·배경 화자 활동 커널을 더하고(P1 과 같은 식, 인코더 **뒤**), 자기 주의 층 4 개(층마다 왼쪽 64 · 오른쪽 2 프레임 — 앞보기 합 0.64 s, 인코더의 0.24 s 와 합쳐 δ10 수준)를 지난다. 마지막 투영을 0 으로 두어 시작은 원래 특징 그대로다. Z 는 값이 작아(표준편차 약 0.045) 헤드 안에서는 크기 1 근처로 맞춘다.
  - 헤드 출력을 원 모델의 언어 프롬프트 융합·RN-T 디코더·joint(28.9M, 같이 학습)로 읽어 대상 화자의 말을 맞힌다. 학습 전에는 우리 인코더 특징도 원 디코더로 읽힌다(섞인 소리에서 우세한 말을 쓴다 — 대상 화자 손실 2.58, 원 인코더 2.27).
  - 학습은 P1 과 같은 셋·창(10–30 s, GPU 당 360 s × 8), 6,000 step. 여러 GPU 의 기울기를 실제로 합치고(손실을 DDP forward 로 계산) 저장 때 rank 사이 가중이 같은지 확인한다.
  - 평가는 P1 과 같은 AMI eval 30 s 조각 방식·같은 셈(`ssa_probe_report.sh`, 판 head-n3d·head-oracle)이다.
- **읽는 법**(AMI eval 둘 겹침 놓침, IHM-mix / SDM — 견줄 값: E13 한 스트림 42.7 / 48.9 %, Parakeet 같은 조각 방식 22.8 / 33.0 %)
  - 헤드의 혼자 말 놓침이 E13(12.8 / 16.4 %)·Parakeet(9.0 / 14.4 %) 근처여야 읽는 쪽이 충분히 학습된 것이다. 혼자 말이 크게 나쁘면 겹침 수치는 읽지 않는다.
