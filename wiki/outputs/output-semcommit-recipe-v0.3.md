# semcommit 라벨링 레시피 v0.3

## 질문
골드셋 대조([[output-semcommit-gold-v1]])에서 v0.2 교사 라벨은 A 정밀도 0.78–0.92 를 지키지만 실제 확정 자리의 14–31 % 만 A 로 잡았다.
원인은 (1) Stage A 후보가 실제 확정 자리의 21–32 % 를 놓치고, (2) 등급이 “판정자 전원 SAFE” 라 약하게 일치하는 두 판정자(κ 0.12–0.21)의 교집합만 남으며,
(3) LLM 이 만든 N(금지)이 42–68 % 만 맞는다는 것. 본 학습 전에 레시피를 고쳐 A 정밀도 ≈ 0.9 를 지키며 재현율을 올릴 수 있는가, 고친 라벨로 학습한 모델은 골드 기준으로 나아지는가.

## 요약
- **최종 레시피 v0.3.3**(기본값; `vapasr/data/semcommit_llm.py` RECIPE_V3, `semcommit_teacher.py grade --recipe v0.3`):
  (1) 후보 = Stage A ∪ 마지막 단어 · 구간 끝 · 참조 전사의 문장 끝 구두점(. ? !),
  (2) A = 가지(구두점 / 대답어 구두점 / 그 외)별 P(SAFE) 평균·P(REVISION) 임계값, 골드 dev 절반에서 가지마다 정밀도 ≥ 0.90 으로 조정(`semcommit_gold.py tune`),
  (3) N = 사람 전사 표지 + **규칙 음성**(스트림 머리 대답어, 한국어 연결어미로 끝난 단어 — 말끝·문장 중간; 후보가 아니어도 N), LLM 이 만든 N 은 버림, 나머지 B(가림).
- **교사 라벨 대 골드(v0.2 → v0.3.3)**: 후보 재현 0.68–0.79 → 0.79–0.94, **A 재현율 0.14–0.31 → 0.70–0.82**, A 정밀도 0.78–0.92 → 0.89–0.99, N 정밀도 0.42–0.68 → 0.99–1.00.
  임계값을 고르지 않은 test 절반: 영어 A P 0.955 / R 0.725, 한국어 0.926 / 0.814.
- **모델(같은 학습 설정, `<SEM_END>` 만, δ4) 대 골드, 최고 F1**: 영어 낭독 0.35(r1, v0.2 라벨) → **0.80**(r5, v0.3.3), 영어 대화체 0.11 → 0.71(학습에 대화체 없음),
  한국어 짧은 발화 0.75 → **0.84**(P 0.85 / R 0.83), 긴 발화 0.71 → **0.80**(0.77 / 0.84). WER / CER 은 네 셋 모두 학습 전 기준 이하, 지연 p50 0.32–0.36 s 그대로.
- **과정에서 고친 것**: 언어 전체 floor 는 정밀한 구두점 가지의 여유로 부정확한 그 외 가지를 켰다(v0.3 영어 학습 A 의 25 %, 정밀도 ~0.3) → 가지마다 floor(v0.3.1).
  한국어 긴 발화 머리의 `네.`·`응.` 은 골드 NO → 대답어 가지(v0.3.2). v0.3 라벨 모델(r3)은 한국어에서 과확정(ks-eval bias 0 P 0.65) — 발화 끝 A 는 많고 음성은 거의 없어서(ks-train N 93)
  “발화 끝·쉼 = 확정” 을 배운 것으로 보인다 → 골드로 검증한 규칙 음성(ks-train N 2,619)으로 bias 0 정밀도 +0.10–0.11, 최고 F1 +0.02–0.03(v0.3.3, r5).
- **지금 8B 교사로는 A = 참조 전사 구두점**: 그 외 가지는 어떤 임계값도 dev 0.90 을 못 넘어 꺼진다. 구두점을 숨긴 재주석으로 “구두점 → COMMIT” 이 주석 순환이 아님을 확인했다.
- 스트림 길이 섞기는 미뤘다: 근거였던 길이 지름길은 `<TURN_END>` 의 것이고 Phase 1 은 `<SEM_END>` 만 배운다. SEM 의 길이 의존은 재지 않았다.

- 쉼표는 후보로 넣지 않았다: ls-test 쉼표 자리 545 개 중 골드 NO 391(72 %).
- 임계값 조정: 골드 스트림을 sha1(id) 짝홀로 dev / test 반씩 나누고, dev 에서 가지마다 정밀도 ≥ 0.90 중 재현율 최대 임계값(격자: 구두점 가지 t_s 0–0.9 · t_r 0.05–1.01, 그 외 t_s 0.30–0.95 · t_r 0.02–0.5), 넘는 값이 없으면 그 가지를 끈다. 규칙 음성 자리는 A 후보에서 뺀다. test 절반은 보고용.
- 대답어 목록(`RESPONSE_TOKENS`)은 골드 지침 관례(“긴 발화 머리의 대답어는 NO, 그 말만으로 끝나면 COMMIT”)에 맞춰 대답어·맞장구만(한국어 20 개: 네·예·응·어·음·아·아니야·맞아·그렇지·그래 …, 영어 14 개: yeah·yes·no·okay·right·oh·well …).
- **규칙 음성**(골드 COMMIT / AMBIG / NO, 두 절반 합):

  | 규칙 | 자리 | 골드 | ks-train N |
  |---|---|---|---:|
  | `reply_prefix` | 스트림 머리의 대답어 연속(스트림 마지막 단어 제외) | 0 / 0 / 117(영어 6 포함) | 418 |
  | `conn_final` | 한국어 마지막 단어가 연결어미(-고·-서·-면·-니까·-지만·-다가·-면서·-가지고), 구두점 없음 — 말끝 -는데(골드 AMBIG)·문장 끝 -더라고·인용 -다고 제외 | 1 / 2 / 54 | 123 |
  | `conn_mid` | 그 앞 한국어 단어의 연결어미·-는데, 구두점 없음 | 0 / 5 / 494 | 1,985 |

  후보가 아니어도 N 행(stageA 거짓)을 만든다 — SemCommitDataset 은 N 에 hardneg_weight(1.0)를 주므로 이 자리는 암묵 음성(NEXT 0.15/0.3)보다 세게 배운다.
- 판(모두 같은 코드·같은 교사 행): v0.3 = 언어 전체 floor, v0.3.1 = 가지별 floor, v0.3.2 = + 대답어 가지, **v0.3.3 = + 규칙 음성**(기본). `grade --neg-rules ''`·`punct_resp` 키 없는 임계값 파일로 이전 판이 재현된다.
- 교사 구성은 v0.2 와 같다: Qwen3-8B(A·B·C) + EXAONE-3.5-7.8B(B), 프롬프트 `semcommit-prompt-v0.2+ab90c940`. 추가 후보만 새로 채점(rack4 GPU 0).

## 3. 구두점 순환성 점검
골드 주석자는 참조 전사(영어 구두점 전사, 한국어 Kspon 원 전사)를 보고 판정했으므로 “구두점 자리 = COMMIT” 이 주석 과정에서 생긴 것일 수 있다.
구두점을 숨긴 단어열만으로 같은 지침(GUIDELINE.md)을 적용해 120 스트림(영어 ls-test 20 · gs-test 20, 한국어 ks-eval 40 · ks-long 40)을 다시 주석했다(Claude, 골드와 독립).

| | 구두점 자리 골드 COMMIT → 재주석 C / AMBIG / NO | 골드 NO → 재주석 COMMIT | 구두점 자리 COMMIT F1 | 전체 COMMIT F1 |
|---|---|---:|---:|---:|
| 영어 | 109 → 102 / 7 / 0 | 0 | 0.958 | 0.961 |
| 한국어 | 77 → 61 / 15 / 1 | 0 | 0.871 | 0.851 |

구두점이 없어도 같은 자리를 확정으로 본다 — 구두점 전사는 확정 자리의 좋은 대리이고 골드 정밀도는 구두점 노출로 부풀지 않았다. 한국어는 구두점 자리 5 개 중 1 개가 AMBIG 로 내려가 재현율은 다소 낙관적이다.

  비슷한 정밀도끼리 비교해도 낫다: 한국어 짧은 발화 P / R 0.84 / 0.67(r1 +2) → 0.85 / 0.83(r5 −2), 긴 발화 0.74 / 0.61(r1 +1) → 0.77 / 0.84(r5 −2).

  28 개가 가림(B) 후보 자리(살펴본 예는 모두 연결어미로 끝난 발화 끝). r5 는 같은 bias 에서 골드 NO 70(후보 아닌 자리 45), 정밀도 0.65 → 0.76(긴 발화 0.51 → 0.61), 재현율 −0.01–0.02.
- **영어는 r3 ≈ r5**(그 외 가지를 뺀 v0.3.1 이후 라벨; bias 0 정밀도 0.78 → 0.84, bias 를 따라 움직인 곡선은 거의 같다). 남은 영어 오판은 후보 아닌 자리의 확정(r3 ls-test bias 0 골드 NO 107 중 75)이 많다.
- **운영점이 언어마다 다르다**: 최고 F1 이 영어는 bias 0 – +2, 한국어는 −2(추정: 한국어 A 의 절반 이상이 발화 끝이라 확정 쪽으로 기운다). 배포·평가는 언어별 bias 를 둔다.
- 남은 한국어 오판(r5 ks-long bias −2 골드 NO 38): 다시 말하기·반복(`일 학 일 학이 어디야 ‖ 이 학 이 학`), 규칙이 못 잡는 축약 -ㄴ데(`한데`·`인데`), 명사구 중간 쉼.

## 5. 해석과 다음
본 라벨링(mxc, 전 코퍼스) 실행 절차는 [[task-semcommit-main-labeling]] — 판정 LLM 은 EXAONE-4.0 · Qwen3.8-27B 만 쓴다(사용자 결정 2026-09-24).

1. **작은 교사로는 LLM 판정이 구두점 이상을 보태지 못한다**. A 는 사실상 참조 전사 구두점(대답어 단위 제외)이고, 품질을 올린 것은 후보 추가·가지별 floor·골드로 검증한 규칙 음성이다.
   전사에 구두점이 없는 코퍼스는 A 가 거의 안 생긴다(본 학습 대화체 코퍼스마다 구두점 유무를 먼저 확인) — (a) 큰 교사의 그 외 가지가 floor 를 넘는지 mxc 교사 관문에서 보거나, (b) 구두점 복원 모델로 `punct_final` 을 만들고 그 정밀도를 골드로 다시 잰다.
2. **mxc 교사 관문**(`experiments/semcommit_teacher_gate.sh`, 기본 `RECIPE=v0.3` — 추가 후보 채점 → 가지별 조정(규칙 음성 자리 제외) → 등급(규칙 음성 포함) → 골드 대조). 본 라벨링은 그 `thresholds.json` 을 쓴다.
   기존 교사 행으로 돌린 dry run(Stage A/B/C 는 행을 미리 두고 건너뜀)이 labels v0.3.3 의 임계값·골드 점수와 일치했다.
3. 규칙 음성은 한국어 형태론(연결어미)과 대답어 목록에 기대므로 NIKL·71631 대화에도 그대로 적용된다. 영어 대화체에는 대응 규칙이 없다(영어 오판은 후보 아닌 자리가 주 원인 — 다음 과제).
   다음 규칙 후보: 축약 -ㄴ데(받침 ㄴ + 데), 반복·다시 말하기 직전 — 모두 골드로 먼저 잰다.

## 불확실성
- 임계값·가지·규칙은 골드(주로 dev 절반, 규칙은 두 절반의 오판 분석)를 보고 만들었다. test 절반은 작아(영어 COMMIT 262 · 한국어 215) ±0.04–0.05 로 읽어야 하고, 규칙 음성과 대답어 가지는 두 절반을 합친 오판 분석에서 나와 test 점수가 약간 낙관적일 수 있다.
- 골드·순환성 재주석 모두 Claude 가 했다(사람 검수 없음). 대답어 가지·규칙 음성은 골드 지침 관례를 라벨로 옮긴 것이라 관례가 바뀌면 다시 본다. 임계값은 교사 구성마다 다르다.
- 모델 비교는 한 번씩의 소규모 학습(각 ~8 분)이라 bias 한 칸 차이의 우열은 가리지 않는다. r2(N 가중 끔)는 r1 과 비슷해 표에서 뺐다(`analysis/models-compare.txt`).
- v0.3.1 등급 행의 `why` 에는 꺼진 가지가 `v3_other+p_safe_low` 로 적혀 있다(등급은 같고, v0.3.2 부터 `v3_other+off`).
