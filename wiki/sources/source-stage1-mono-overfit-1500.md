# Stage 1 mono overfit 1,500-step 완료

## 무엇인가

EN·KO 각 16개 고정 표본에서 실행한 mono 스트리밍 ASR overfit의 최종 결과와,
새 정규화·정렬 규약을 사용하는 `overfit-v2` 자동 실행 조건을 기록한 실험 자료다.

## 수렴 결과

| step | EN WER / `viol80` | KO CER / `viol80` | 판정 |
|---:|---|---|---|
| 300 | 0.917 / 72.7% | 0.364 / 2.9% | 미수렴 |
| 600 | 0.141 / 7.3% | 0 / 0 | KO 수렴, EN 진행 중 |
| 900 | 0 / 0 | 0 / 0 | 기능 관문 통과 |
| 1200 | 0 / 0 | 0 / 0 | 유지 |
| 1500 | 0 / 0 | 0 / 0 | 유지 |

@1500 지연은 EN p50/p90/p99 = 201/231/240 ms, KO = 189/232/312 ms다.
두 언어 모두 `delta=2` 설계 지연 160 ms와 정렬 오차 위에 모였고, tok/chunk도
참조율과 정확히 같으며 M 강제는 0이다.

이 결과로 @600의 EN 선행 방출 꼬리는 영구적인 방출 규약 오류가 아니라 내용 학습의
미수렴과 함께 사라지는 현상으로 판단한다. 개별 @600 토큰에서 반복어 매칭 잡음이
얼마나 섞였는지는 따로 감사하지 않았으므로 그 비율까지 단정하지 않는다.

## tick 해석

@1200 이후 tick p99 679–755 ms는 정렬·특징 추출 작업이 같은 GPU에서 겹친 측정이라
모델 간 속도 비교에서는 제외한다. 그러나 경합 전 @600의 decoder-only p99도
151–186 ms로 80 ms deadline을 넘었다. 따라서 **overfit 기능 관문은 통과했지만
실시간성 관문은 아직 통과하지 않았다.** 한가한 GPU의 단독 end-to-end 측정이 필요하다.

## 새 규약 재검증

서버 대기 체인은 `align2/kspon-100` 완료 신호와 LibriSpeech 정렬 파일 13,182개를
확인하면 `overfit-v2`를 900 step으로 시작한다. 확인 항목은 다음 두 가지다.

- 숫자 이중표기를 한글 읽기로 바꾼 KO 표본의 CER 0·p50 약 190 ms·`viol80=0`
- 발화 경계 선행 공백 정렬로 LibriSpeech의 `losti` 같은 토큰 결합이 사라지는지

새 규약은 기존 데이터와 다른 문제를 드러낼 수 있으므로 @900에서 완전 수렴하지
않더라도 즉시 실패로 보지 않고 필요하면 @1500까지 연장한다.

### 표본 선택 확인

현 `--overfit 16`은 전체 데이터 항목을 seed 0으로 섞은 뒤 앞 16개를 택한다. 따라서
선택된 KO 16개에 숫자 이중표기 변경 사례가 포함되거나, EN 16개에서 문제의 발화
경계 결합이 나타난다는 보장은 없다. `overfit-v2` 시작 시 선택 ID와 다음 coverage를
함께 기록해야 한다.

- KO: 구규약 대비 정규화 타깃이 달라진 선택 발화 수
- EN: 두 발화 이상을 연결한 선택 stream 수와 경계 tokenization 검사 수

어느 coverage든 0이면 900-step overfit 통과는 전체 학습 경로의 회귀가 없다는 뜻일
뿐 해당 수정의 검증은 아니다. 변경 KO 표본과 경계 EN 표본을 명시적으로 고른 작은
회귀 검사를 별도로 실행한다. 평가 로그의 `example`은 첫 문자열 60자만 보여 주므로
그 자체로 모든 발화 경계를 검증하지 못한다.
